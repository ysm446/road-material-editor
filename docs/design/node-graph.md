# node-graph — ノードグラフの設計

作成日時: 2026-09-02 12:50
更新日時: 2026-09-07 08:30

`src/graph/` とグラフパネル（`src/app/ApplicationGraphPanel.cpp`）の設計。
ノード編集と移行前の評価経路、Road / Mesh Output による道路メッシュの評価を記録する。
新しい型と移行順序は [plan](../plan/plan.md) を参照する。

## Road Editorの実寸Path（2026-09-06）

新規Pathは地形から独立した実寸カーブ。以下の地形UVに関する旧設計は旧形式のPathだけに適用する。
Ctrl＋クリックはY=0の無限平面へ点を配置し、選択点から延長すると同じYへ置く。
グリッド表示やメッシュの有無は配置を制限しない。平面と平行な視線・視点の後方には配置しない。
点と曲線標本はx/y/zを保持する。移動ギズモはX（赤）・Y（緑）・Z（青）の3軸で、選択の3次元重心に表示する。
中央ハンドルはXZ平面移動。軸方向のドラッグでは開始時の投影換算率を使い、Yだけを動かしてもX/Zは変わらない。
XYZの数値入力も点のプロパティで行える。2次ベジェ・3次Bスプラインは3軸を同じ基底で補間する。
クロソイドは道路のXZ平面線形と高さ補間を維持する。
旧Pathは「実寸カーブへ変換」で制御点と経路内部点を固定し、地形への追従を解除する。
Mask Path / Areaへ渡す際は評価対象のサイズに応じてUVへ変換する。
道路生成はこのカーブの実寸サンプルを入力とする（後述の「Road / Mesh Output」）。

## データモデル（`graph/NodeGraph.h`）

- **単一 ID 空間**: ノード・ピン・リンクはすべて同じカウンタ（`GraphId = int`）から
  採番する。imgui-node-editor の `NodeId / PinId / LinkId` にそのまま渡せる。
  読み込み時は全 ID の max+1 から採番を再開する。
- **値の型**: `ValueType` は `Material`（PBR チャンネルセット）と
  `Mask`（0〜1 の 1 チャンネル）、`Path`（旧地形パス）。同じ型どうしだけ繋がる。
- **ピン**: `{ id, nodeId, kind(Input/Output), valueType, label }`。
  接続できるのは「別ノード + 型一致 + 出力→入力」で、**循環になる接続は
  `CanCreateLink` が弾く**（下流を DFS して生産側に届くか見る）。
  入力ピンは 1 本だけ。新しい接続は既存を置き換える。
- **設定は variant**: ノード種類ごとの設定構造体を `NodeSettings`
  （`std::variant`）で持つ。terrain-editor の「全種類の設定を 1 構造体に持つ
  ファット構造体」はやめた。
- **位置はノードが持つ**（`posX / posY / positionValid`）。terrain-editor は
  UI 側だけが持っていて保存時に吸い出していたが、こちらはデータモデルに含めて
  保存も素直にした。エディタとの同期はグラフパネルが行う
  （描画後に `ed::GetNodePosition` で書き戻し、読み込み後は
  `RequestGraphNodePlacement()` で流し込む）。

## 評価 — マスクは DAG、合成はレイヤー列

グラフは 2 つの経路へ落ちる。

```
グラフ ─┬→ レイヤー列（下から上）      … 合成（既存の GPU 評価器）
        └→ マスクの op の列（DAG）     … マスクを 1 枚ずつテクスチャへ焼く
```

- **マスクはノード単位で評価する。** `CompileChainFrom()` がマスクのノードを
  `compositor::MaskProgram`（op の列）へ落とし、評価器が op ごとに
  1 枚のテクスチャへ焼く。中間結果が残るので**合流（Mask Blend）**も、
  同じマスクを 2 か所で使うこともできる。同じノードは 1 つの op を共有する。
- **op は自分より前だけを入力にする**（コンパイルが依存順に並べる）。
- **高さを読む op（川筋 / 傾斜）は、チェーンのどこまで合成した Height を使うかを持つ**
  （`MaskOp::heightSourceLayer`。Base 入力で指す）。評価器は合成ループの中で
  その位置を通過した時点に焼き、上のレイヤーがそれを読む。
- **焼き直しは入力ハッシュで判断する**（`MaterialEvaluator::m_maskOpHashes`）。
  ハッシュには「op のパラメータ + 入力 op のハッシュ + そこまでのレイヤーの
  **Height に効く値** + 地形の実寸」を混ぜる。色やラフネスを触っても、
  川筋のような重い op は焼き直さない。
- 合成そのもの（レイヤー列）はまだ線形で、こちらはノード単位のキャッシュを持たない。
  メッシュ用の評価経路は線形合成とは分けて追加する。

## 評価 — レイヤー列へのコンパイル

グラフ独自の評価器は（まだ）持たない。`NodeGraph::CompileLayers()` が
出力ノードの「マテリアル」入力から「下地」チェーンを遡り、
**レイヤー列（下から上）へ落とす**。それを `MaterialStack` に入れて
既存の GPU 評価器（`MaterialEvaluator`）へ流すので、
**合成規則も見た目もレイヤー時代と完全に一致する**。

- Application は `m_graph.Revision()` とプレビュー対象を見て、変わったときだけ
  再コンパイルする（`SyncGraphStack()`）。コンパイルはレイヤー設定のコピーだけなので安価。
- **プレビュー対象のノードまでのチェーンを合成する**（`CompileLayersTo()`）。
  対象は出力ピンのクリックで決まり、**選択とは別**。書き出しも同じ対象を使う
  （見えているものを書き出す）。
- **対象はノードではなく出力ピン。** `CompileLayersTo(nodeId, outputPin)` は
  そのピンの型で分岐し、**Mask なら結果を白黒で貼ったプレビュー**にする。
  堆積のように Result と Mask を両方出すノードがあるので、
  ノードの種類だけでは「何を見せるか」が決まらない。
  ピンの指定が無い（0）ときは最初の出力を見る。
- レンダラと書き出しは常にコンパイル結果のスタック（`m_graphStack`）を使う。
- 出力ノードに何も繋がっていなければ下地 1 枚（`MakeBaseLayer`）で補う。

この経路は移行前の材質評価用。メッシュにはデータを返す独立した評価器を追加する。

## ノードを 1 種類増やす手順

1. `graph/NodeGraph.h` — 設定構造体を定義し、`NodeSettings` の variant へ足す。
2. `graph/NodeGraph.cpp` — ピン構成の constexpr 配列と `kNodeDefinitions` の行を足す。
   `CreateNode` の設定の初期化に分岐が要るなら足す。
3. `io/ProjectIo.cpp` — `WriteGraph` / `ReadGraph` に設定の読み書きを足す。
4. `app/ApplicationGraphPanel.cpp` — 追加メニューの項目と、
   プロパティペインの設定 UI を足す。
5. 評価に関わるなら `CompileLayers`（または将来の評価器）へ意味を足す。
6. 入出力・単位・保存仕様を該当する設計資料に記録する。

## UI（グラフパネル）

- imgui-node-editor（vcpkg `imgui-node-editor`）。docking 版 ImGui と共存できる。
- エディタのコンテキストは `ed::Config::SettingsFile = nullptr` で作る
  （位置は自前で保存するため。エディタの json は使わない）。
  パン操作は中ボタン（`NavigateButtonIndex = 2`）。
- 背景はドットグリッドを自前で描く（既定のグリッド線は透明にする）。
- **ピンと線の色は型で決まる**（`PinTypeColor`）。Material が緑、Mask がオレンジ、
  Path が水色（ビューポートに描くパスの点と線も同じ系統）。
  値は terrain-editor に合わせた（あちらの HeightField がこちらの Material）。
  明度が近く色相だけが離れているので、暗い盤面でどちらも同じ強さで読める。
  繋ぎ間違いに色で気づけるようにするためのもの。
- ノードのカードは「種類色の印 + レイヤー名 + 種類名」のヘッダと、
  左に入力ピン列 / 右に出力ピン列（24px ピッチ）。丸ピンは
  `ed::PinRect / PinPivotRect` で当たり判定と接続点を指定する。
- **幅はピンのラベルが重ならない所まで広げる**（下限 200px）。入力は左、出力は
  右へ寄せるので、同じ行に並ぶ 2 つのラベルの合計が要る幅になる。固定幅にして
  いたときは、Mask Blend の `Foreground` / `Background` が出力の `Mask` と
  重なって読めなかった。
  **当たり判定はラベルまで広げる**（`ed::BeginPin` の中でラベルも描き、
  丸とラベルを合わせた矩形を `PinRect` に渡す）。丸だけだと 14px 角しかなく、
  接続も出力ピンのクリック（プレビューの切り替え）も狙いにくい。
  接続点（`PinPivotRect`）は丸のままなので、リンクの端は丸に付く。
- **ノードにサムネイルを出す**（`ui::kNodeThumbnail` = 64px）。繋ぎ替えずに
  中身が分かるようにするため。
  - レイヤーのノード（Heightmap / Surface / Shape / Liquid / 加工）: **そのレイヤーまで
    合成した結果**。アルベド（BaseColor）に、同じ時点の Height の粗い勾配で固定 1 灯の
    陰影を付けたもの（`CompositeThumbnail.hlsl`）。評価器が合成ループでレイヤーを
    走らせた直後に 64² へ落とす（`MaterialEvaluator::LayerThumbnailHandle()`）。
    ラフネスや Normal チャンネルの細部、天球の照明は使わない（64px では読めないし、
    固定の光のほうがノードどうしを見比べやすい）。レイヤーとノードの対応は
    `CompiledGraph::layerSources`。同じノードが Mask だけの差し込み（maskOnly）で
    先に並ぶことがあるので、後ろから探して本流のほうを取る。
  - Mask 出力を持つ加工ノード（堆積 / 崩落 / 積雪 / 河川 / 水滴侵食 / スキャッター）は、
    結果の隣に最初の Mask 出力の白黒も出す。
  - マスクのノード: 焼いたマスクの白黒。評価器が op ごとの結果を
    64² へ落として持つ（`MaterialEvaluator::MaskOpThumbnailHandle()`）。
  - **op はプレビュー対象のチェーンに入っているノードにしか無い。** 見ていない枝の
    マスクノードは枠だけの空き（未評価）になる。
  - **op の添字とノードの対応は、スタックの版ごとに控える**
    （`Application::m_graphMaskOpSources`）。評価は非同期なので、表側の結果は
    いまのコンパイルより古いことがあり、そのままの添字で引くと別のノードの模様が出る。
    評価器の `EvaluatedRevision()` に合う版の対応で引く。
  - サムネイルは表裏の 2 組を合成結果と一緒に入れ替える（評価中に ImGui が読む側へ
    書かないため）。**op を焼き直したかどうかに関わらず毎回落とす。** op のハッシュは
    1 組しか無いので、裏側の添字 i が「前のまま」とは限らない。
  - マスクは 1 チャンネル（R16_FLOAT）なので、ImGui へは R を RGB へ配った SRV を渡す
    （既定の SRV だと赤一色になる）。テクスチャ一覧のチャンネル表示と同じ作り。
- パネルは上下 2 段（上: エディタ / 下: 選択ノードのプロパティ）。
  境界は `ui::HorizontalSplitter`。
- **既定の置き場所は右カラムの前面タブ**（グラフ / レイヤー / …）。
  中央のタブにするとビューポートと排他になり、ノードを選んだ結果を
  プレビューで確かめられない。盤面の広さより「繋ぎ替えて見た目を確かめる」
  往復を優先した。
- **プレビュー対象と選択は別。** ビューポートに出すノードは
  **出力ピンのクリック**（またはノードのダブルクリック）で決め、
  プロパティに出すノードは**選択**で決める。
  結果を見ながら別のノードのプロパティをいじれるようにするため
  （terrain-editor と同じ作法）。背景のダブルクリック、または
  プロパティ上の「出力へ戻す」で出力ノードのチェーンへ戻る。
  - 出力ピンは押した瞬間からリンクのドラッグが始まるので、
    **同じピンの上でほとんど動かさずに離したとき**だけクリックとみなす。
  - プレビュー中のノードは**枠を明るく**し、名前の右に ● を添える。
    **見ている出力ピンは丸を塗りつぶす**（出力が 2 つあるノードで、
    Result と Mask のどちらが出ているのかが分かるように）。
    プロパティ上のプレビュー行にもピン名を出す。
  - 選択（プロパティ）はエディタの選択をそのまま使う。ペイントの対象も選択側。
- **コピー / 貼り付けは Ctrl+C / Ctrl+V**（キャンバスの上にいるときだけ拾う）。
  枠で囲んだ複数選択にも効く。貼り付けでは、
  - **コピーした集合の中どうしの接続**は貼った側で繋ぎ直す。
  - **集合の外から来ている入力（親）は、元の親へ繋いだまま**にする。
    複製したノードがすぐ同じ下地で動くようにするため。
  - **出力側（自分を使っていた下流）は繋がない。** 入力ピンは 1 本しか
    持てないので、繋ぐと元のノードから奪ってしまう。
  - 出力ノードはコピーしない（1 つだけ繋ぐ前提のノードなので）。
  - **貼る先は今のキャンバスの中央**（集合の中心をそこへ置き、集合の中の相対の
    配置は保つ）。コピー元が画面の外にあっても、貼ったノードが見えない所へ
    行かないようにするため。中心はノードの大きさまで含めて出す
    （位置だけだと左上しか分からず、右下へずれる）。
  - 貼るたびに位置を少しずらす（同じ場所に重ねると貼れたか分からない）。ずらしは
    4 回で一巡させる（増やし続けると、貼るほど中央から遠ざかる）。
- ノードの追加は背景の右クリック（追加位置は右クリック地点。視界内へクランプする）。
  削除は選択して Del（エディタ既定）。A でグラフ全体を画面に収める
  （ホバー判定は `ed::Begin` より前のスクリーン座標で取る）。
- **`ed::NavigateToContent` はノードを描いた後に呼ぶこと。** 内容の矩形は
  そのフレームで live なノードから計算されるため、描画前に呼ぶと空矩形で
  何も起きない。さらにエディタはキャンバスのサイズ変化のたびに前の表示領域を
  復元する（`ed::Begin` 内）ので、ドック確定を待ってサイズが安定した
  フレームで呼ぶ（`m_graphNavigateCountdown`）。
- **エディタのフレーム内では `io.MousePos` がキャンバス座標に差し替えられている**
  （imgui_canvas が Begin で変換する）。フレーム内の `ImGui::GetMousePos()` は
  そのままキャンバス座標として使えるし、**使わなければならない**。
  `ed::ScreenToCanvas` を重ねると二重変換になり、ノードが視界の外へ飛ぶ
  （実際に踏んだ）。スクリーン座標が要る判定（ホバーなど）は Begin より前に取る。
- **`ed::GetNodePosition` は知らないノードに `(FLT_MAX, FLT_MAX)` を返す。**
  右クリックで作ったばかりのノードは、そのフレームではまだエディタに
  登録されていない（描画は次のフレーム）。フレーム末尾の位置の書き戻しが
  この FLT_MAX を信じて保存すると、次の流し込みでノードが無限遠へ飛び、
  **キャンバスの座標計算が壊れて操作不能になる**（実際に踏んだ）。
  書き戻し・流し込み・ファイル読み込みの 3 か所で座標を検証している
  （`IsValidNodePosition`。非有限と |v| > 1e6 を弾き、壊れた座標は
  ビュー中央へ置き直す）。

## 制限（既知・今後の対応）

- **アンドゥは対応済み**（ノード / リンク / 設定 / 位置を文書スナップショットで持つ）。
  ただし**ノードの移動だけでは段を積まない**。位置は毎フレーム UI から返ってくるため、
  移動を段にすると 1 ドラッグが無数の段になる。位置は他の変更の段に相乗りする。
- **マスクは DAG（合流あり・ノード単位のキャッシュあり）だが、
  合成（レイヤー列）はまだ線形**で、キャッシュも持たない。
  マテリアル側の合流（2 つのチェーンを混ぜる）は今後の課題。
- ペイントの対象は「グラフ有効時は選択中ノードのレイヤー」
  （`Application::CurrentPaintLayer`）。
- 選択もプレビュー対象も保存しない。開き直すと出力ノードのチェーンから始まる。

## Road / Mesh Output

`Path → Road → Mesh Output` で道路を表示する。Roadは幅とUV反復長を持ち、RoadSurface（Mesh）、Left / Right（Path）を出す。左右は進行方向基準。境界もRoadの入力に接続できる。

複数Mesh Outputは同時に表示する。未接続・不正な枝は空となり理由をプロパティ領域に表示する。生成処理はCPUデータを返し、グラフ改版時にフレーム外でGPUへ転送する。Mesh Output表示中は旧地形プレビューより優先する。

### 部分描画と途中経過の表示（2026-09-07）

- 鎖は Road を起点に Lane Marking / Decal が部品を積む。**部品の生成が失敗しても道路面までの部品は残し**、失敗したノード名と理由を「 / 」区切りでプロパティ領域に出す（`CompiledMeshGraph::error`）。Road 自体が失敗したときだけ、その枝は空になる。
- Road / Lane Marking / Decal の出力ピンをクリック（またはノードをダブルクリック）すると、**そのノードまでの鎖だけ**をメッシュシーンに出す（`CompileMeshGraph(graph, previewNodeId)`）。Mesh Output が無くても表示できる。背景のダブルクリックか「Mesh Output へ戻す」で全 Mesh Output の表示に戻る。2D の合成プレビューには影響しない。
- **Merge ノード**（2026-09-07）。Mesh 型の入力を可変長に持ち、繋いだ枝を順に 1 つの RoadSurface にまとめる。入力は「繋がっている本数＋空き 1 本」を常に保つ（`NodeGraph::NormalizeVariablePins`。リンクの作成・削除・ノード削除・`Replace` の後に整える）。
  - **重複除去**。鎖の各メッシュは作ったノードの ID を鍵に持ち（`MeshChain::sources`）、同じノード由来のメッシュは 1 回だけ積む。Road → Merge と Road → Decal → Merge のように同じ Road を 2 つの枝から入れても道路面は 1 枚。押し出し元（`displacementSource`）は写した先の番号へ付け替える。複数の Mesh Output にまたがる重複も同じ仕組みで除く。
  - 下流の Lane Marking / Decal は **Mesh 1 の枝の面**に乗る（chain.road は最初の枝のもの）。
  - 途中ノードの表示で Merge を選ぶと、まとめた結果がそのまま出る。

## 道路の分割・確認表示

Roadは約1 m四方のセルを三角形2枚で構成する。カーブ・端のセルは変形する。道路の1 m目盛りは実距離UVから描き、UVチェッカーは実際のUVの反復・伸縮を可視化する。どちらもビューポートの「表示」でオン・オフし、生成メッシュの保存値や材質は変更しない。

## 道路線形の縦断曲線とバンク角（2026-09-07）

実寸 Path に縦断ポイントとバンクポイントを置き、Road が生成時に反映する。計算は road-editor
（D:/GitHub/road-editor）の docs/calculation 02・03 を移植した（`src/graph/RoadProfile.h`）。

- 縦断ポイント: 線形の正規化位置 u、縦断曲線長 VCL、オフセット。始点・各ポイント・終点をガイド点にし、
  前後の勾配を放物線でつなぐ。VCL は前後区間に収まるよう短縮する。オフセットは制御点から決まる高さへの加算で、
  ポイントが無ければ高さは変えない。
- バンクポイント: u、設計速度、自動 / 手動、角度。自動は XZ 平面の曲率半径（前後 10 m の 3 点円弧近似）と
  設計速度・摩擦係数から theta = atan2(a − g·f, g + a·f) で求め、曲がる向きの符号を掛ける。
  正で Left 側（列 0）が上がる。Left へ曲がる左カーブは負（内側の Left が下がる）。
  手動ポイントを含む区間はポイント間で線形補間し、最初 / 最後の手動ポイントの外側はその値を保つ。
  ガウス平滑化（距離指定）は任意。
- Road は縦断かバンクが有効なら直線の線形でも 1 m で刻み直し、行ごとに横ベクトルを接線まわりに回す。
  Left / Right 境界と Lane Marking は行の左右端から補間するのでそのまま追従する。
- 編集はプロパティの「道路線形 > 編集」で制御点 / 縦断 / バンクを切り替える。縦断反映後の中心線を描き、
  Ctrl＋クリックでポイントを置き、マーカーを線に沿ってドラッグする。手動バンクポイントは断面平面のリングを
  ドラッグして回す（回転ギズモ）。`--profile-mode <0..2>` と `--select-path-point` で検証用に状態を再現できる。
- 保存は版11。破線・停止線と同様、縦断の詳細（勾配の数値表示など）は後続。

## 走行側と Left / Right の向き（2026-09-07）

- 走行側（左側通行 / 右側通行）はプロジェクトで 1 つ。`NodeGraph::RoadNetwork()` が持ち、`graph.roadNetwork.leftHandTraffic` に保存する。
  プレビュー設定の「道路」で切り替え、Road / Lane Marking のプロパティには表示だけ出す。アンドゥの対象。
- Road の Left / Right は進行方向に向かっての左右（右手系 Y-up、右 = (−dz, 0, dx)）。格子の列 0 が Right、列末尾が Left。
  以前は列 0 を Left と呼んでいたが物理的に逆だったので改めた。ピンの順序は変えていない。
- 左側通行では Left の車線が線形の向き（Path の from → to）へ進み、Right が対向。右側通行は逆。
  Lane Marking の進行方向の矢印はこの判定で向きを決める。標識などの向きも同じ判定を使う。

### 車線数（2026-09-07）

- Road は `lanesForward`（進行方向、1〜8）と `lanesBackward`（対向、0〜8）を持つ。車線幅は全幅÷合計で、車線ごとの幅は持たない。
- `ComputeRoadLanes(settings, leftHandTraffic)` が Right 端から順に車線の中央と向きを並べる。右側通行なら進行方向の車線が Right 側、左側通行なら対向が Right 側。
  進行方向と対向の境が `centerLateral`（中央線の位置）、同方向の車線の間が `dividers`（破線の位置）。対向 0 なら中央線は無い。
- Lane Marking の中央線は `centerLateral` に引く（道路の中心とは限らない）。車線境界線は `dividers` に破線（長さ・間隔、間隔 0 で実線）で引く。
  破線は `SampleRoadSurface` で距離ごとに帯を作り、行をまたぐ区間は行ごとに刻む。矢印は各車線の中央に、車線の向きで置く。
- Road Mask の轍（`laneOffsetMeters`）はまだ手入力。車線数から自動で置くのは今後。

## Lane Marking（白線）

`Road → Lane Marking → Mesh Output` で道路面の上に白線を出す。入力はRoadSurface（Mesh）とMaterial、出力はRoadSurface（Mesh）。
出力は道路面と白線をまとめた値で、Mesh Outputは上流をたどってRoadを起点に部品を順に積む。Lane Markingを重ねて接続してもよい。

- 帯ポリゴンとして生成する。Roadの格子の各行で左右端の頂点から横位置を補間するため、マイター角やカーブでも道路端と平行になる。
- 中央線は横位置0、外側線は左右の道路端から「端からの距離」だけ内側。線幅は共通。線が道路の外に出る・中央を越える・重なる設定は拒否する。
- 路面の法線方向へ「浮かせ量」（既定5 mm）だけ持ち上げ、深度の重なりによるちらつきを避ける。
- UVは幅方向のUが帯の左端0〜右端1、長さ方向のVが実距離÷UV反復長。Materialに塗料の材質を接続でき、未接続は白の単色。
- 白線メッシュには道路の1 mグリッドを重ねない（`SceneMesh::roadGridOverlay`）。UVチェッカーは適用される。
- 進行方向の矢印: 左右の車線の中央（±幅/4）に一定間隔で置く。走行側の車線は線形の向き、対向車線は逆向き。
  形は軸と三角の 7 頂点で、UV は矢印 1 個に 0〜1。矢印だけでも生成できる。
- 「UV の向き」で長さ方向を V（既定）か U にできる。2048×256 のような横長の白線素材は U。Road にも同じ設定があり、
  帯の道路 UV（押し出し用）は Road 側の設定に従う。
- 設定は保存し、生成結果は再読込時に再構築する。破線・停止線は後続。

## 面上の Path と Decal（2026-09-07）

Path の入力は Surface（Mesh 型）。Road の RoadSurface（Lane Marking / Decal の素通し出力でもよい）を繋ぐと面の座標で保持し、
道路を変えても追従する。Decal は RoadSurface・面上の Path・Material を受け、帯メッシュを作って RoadSurface を素通しする。
旧地形パスの Base（Material 型）はこのピンの前身で、旧ファイルのリンクは型が違うため捨てる。詳細は [road-material-layers](road-material-layers.md)。

## Road Mask と材質スロット（2026-09-07）

Road は Material 1〜4 と Mask 2〜4 を持つ。スロット 1 が下地、2〜4 は Road Mask ノードを Mask 2〜4 へ繋いだ所に出る
（道路空間マスクの R / G / B）。スロットごとに座標（道路 UV / ワールド XZ）と反復長、共通のブレンド幅を持つ。
Road Mask は RoadMask 型の出力 1 本で、形（轍 / 端の減衰 / 長さ方向ノイズ / 一様）と長さ方向のムラを持つ。
詳細は [road-material-layers](road-material-layers.md)。

## Roadのマテリアル入力

RoadはPathとMaterialを入力し、RoadSurface・Left・Rightを出力する。SurfaceなどのMaterial型Resultを任意接続できる。材質チェーンは既存のCompileLayersToでレイヤー・マスクへ変換し、メッシュごとの同期MaterialEvaluatorで合成する。素材の編集・再読込による共通スタックの改版も道路の評価へ伝える。

道路UVの1タイルをUV反復長（m）としてWrapサンプリングする。色・接空間法線・ラフネス・メタルネス・AOを既存PBRへ渡す。ハイトから法線は生成するが、道路形状のディスプレイスメントは行わない。未接続時は従来の単色PBR値を使う。評価結果は保存しない。
