# プロジェクトルートと共有アセット

作成日時: 2026-09-13 23:40
更新日時: 2026-09-15 12:06

terrain-graph の同名の仕組みを移植したもの。「シーンファイルを開く」から「ルートフォルダを設定する」へ切り替え、
テクスチャ・マテリアル・天球・レイヤーマテリアル・境界マテリアルをシーンではなくプロジェクト（ルート）に紐づける。
実装は `src/io/ProjectWorkspace.*`（ルート・永続 ID・分離保存）、`src/io/ProjectIo.*`（共有アセットの読み書き）、
`src/app/ApplicationAssetBrowser.cpp`（帯の UI）、`src/app/AssetThumbnailCache.*`（未読み込みのサムネイル）。

## 所有関係

プロジェクトは実フォルダをルートに持つ。**常に 1 つのルートが開いている。**
起動時は `--root`、無ければ最近使ったルート、それも無ければ `data/`（`TG_DATA_DIR` で変更可能）を開く。
`ファイル > ルートフォルダを開く…`（Ctrl+O）とアセットの帯の「ルートを開く…」で切り替える。
ルート直下の `project.tgproj` は `terrain-graph.workspace` 版 1 の JSON で、プロジェクト ID と最後に保存したシーンを持つ。
同名のファイルが別形式なら上書きせず、開く操作を中止する。**この目印ファイルの `startupScene` は自動読み込みには使わない。**
通常起動は新規シーンで、`--project` で明示したシーンだけを起動時に読む。

シーンは `.tgscene`（`terrain-graph.scene` 版 1）としてルート内の任意の場所に保存する。保存ダイアログの初期値は `Scenes/`。
ルート外へは保存できない。グラフ・配置（surfaceLayouts の形状プリセットと区間）・プレビュー設定・
使用中のマテリアル / 天球 / レイヤーマテリアル / 境界マテリアルの参照はシーンが持つ。既存の保存器の版（`kProjectFormatVersion`）は
`projectVersion` に退避し、読み込み時に `version` へ戻して従来の移行規則をそのまま通す。

画像と HDRI は元のファイルを使う。ルート内のファイルはコピーしない。ルート外から読み込むファイルは、
帯で表示中のフォルダ（ドロップ・`--texture`）または `Imported/`（保存時に見つかった外部参照）へコピーする。
再配布できない素材をリポジトリの `assets/` へ入れない。

## アセット形式

| 拡張子 | format | 内容 |
| --- | --- | --- |
| `.tgmat` | `terrain-graph.material-asset` | 名前、PBR パラメータ、画像の ID 参照 |
| `.tgsky` | `terrain-graph.sky-asset` | 名前、手続き的な空、HDRI の ID 参照、輝度と IBL 倍率 |
| `.tglayer` | `terrain-graph.layer-material-asset` | 名前、凹凸量、ブレンド幅、最大 4 層（または材質グラフ）、各層のマテリアルの ID 参照 |
| `.tgboundary` | `terrain-graph.boundary-material-asset` | 名前、境界マスク / ハイトの画像の ID 参照、幅・繰り返し長・深さ・基準値・軸・反転 |
| 元ファイル名`.meta` | `terrain-graph.source` | 元画像・HDRI の固定 ID |

すべて UTF-8 JSON、版 1。マテリアル・天球・レイヤーマテリアル・境界マテリアルのファイルは編集内容の原本で、再生成できるキャッシュではない。
`.tglayer` / `.tgboundary` の本文は配置データ（`surfaceLayouts.layerMaterials[]` / `boundaryMaterials[]`）の 1 項目と同じ形で、
シーン内の番号で書く参照だけを `{"uid","path"}` に置き換える（参照なしは `null`）。
フォルダ分類は強制しない。置き場所が未定のもの（旧 `.tgproj` から初めて分離するとき、帯の外で作ったとき）だけ
`Materials/` / `Skies/` / `LayerMaterials/` / `BoundaryMaterials/` に名前から作る。
帯の右クリック「マテリアルを作成」「天球を作成」「レイヤーマテリアルを作成」「境界マテリアルを作成」は表示中のフォルダへ作る。
「複製して編集」で作ったレイヤーマテリアルは ID を持たない別のアセットで、次の保存で `LayerMaterials/` へ入る。
**ID を持たないもの（旧 `.tgproj` の埋め込み、単体 `.tgmat`）は、先に同じ中身（ID・形式・版を除く JSON が一致）の
既存アセットを探し、あればその ID とファイルへ保存する**（`ProjectWorkspace::FindIdenticalAsset`）。同じ保存で ID を持つ
別のアセットが使う ID は対象にしない。これが無いと、旧 `.tgproj` を開いて保存するたびに `_1` `_2` の複製が増える。
中身が変わらない共有アセットは書き直さない（更新日時を保ち、サムネイルのキャッシュを無効にしない）。

参照は `{"uid":"固定ID","path":"ルート相対パス"}`。ネイティブ形式は内部に ID を持ち、画像は隣の `.meta` に ID を持つ。
ルートの走査で ID から現在のパスを解決するので、**エクスプローラで改名・移動しても参照は切れない**（`.meta` は一緒に動かす）。
ID が見つからない場合に同名の別ファイルへ黙って付け替えない。ID の重複（エクスプローラでの単純コピー）はエラーにする。
走査はドット始まりのフォルダと、`project.tgproj` を持つ入れ子のフォルダ（別のルート。`data/test/` の検証用ルートなど）には入らない。
持ち出し用の旧 `.tgmat`（`terrain-graph.material`）は ID を持たず、走査の対象外。帯から開くと従来どおりライブラリへ 1 つ足す。

シーン内のグラフ・配置は既存の整数 ID（保存番号）を保ち、シーンの `textures` / `materials` 表を介して永続 ID へ繋ぐ。
レイヤーマテリアル・境界マテリアルは配置データの中で `{"id": SurfaceId, "asset": 参照}` になり、形状プリセットと区間はその番号で指したまま。
共有のレイヤーマテリアルが参照するマテリアルがシーンの表に無ければ、展開時に表へ足す（他のシーンで作ったもの）。
共有化の前に保存した `.tgscene`（配置データに埋め込みのまま）もそのまま読め、次の保存で分かれる。
GPU 用の実行時 ID と永続 ID を混同しない。`MaterialAsset` / `SkyAsset` / `LayerMaterial` / `BoundaryMaterial` は `assetPath` / `assetUid` を持ち、
アンドゥの写しにも入れる（初回保存で付いた ID を、保存前の段へ戻しても保つ）。複製は ID を持たない別のアセットになる。

## 保存と読み込み

「保存」（Ctrl+S）はシーンと読み込み済みの共有アセットを保存する。帯には保存ボタンを置かない（2026-09-15 に「アセットを保存」を削除）。
帯の右クリックで作ったマテリアル・天球・レイヤーマテリアル・境界マテリアルは、作成の直後にファイルへ書く。
共有アセットを編集すると、それを参照する他のシーンは次に読み込んだときに更新後の内容を使う。
シーンとルートの切り替え前には「保存して切り替え / 保存せず切り替え / キャンセル」を出す。

旧 `.tgproj` / `.mmproj` は従来の読み込み器で開く（`ファイル > シーンを開く…`、ドロップ、`--project`）。
通常の保存は別名の `.tgscene` へ行うので移行元は残る。保存の時点で埋め込みのマテリアル・天球・レイヤーマテリアル・境界マテリアルが
`Materials/` / `Skies/` / `LayerMaterials/` / `BoundaryMaterials/` へ分かれ、ルート外の画像は `Imported/` へ取り込まれる。

**リンク切れは保存を止めない。** ファイルの無い画像はパスだけの参照（`{"path": ...}`）で残し、読み込み時は
従来のリンク切れ（`TextureLibrary::AddMissing`）として復元する。繋ぎ直しは従来のテクスチャの右クリックから行う。

シーンの読み込みは、参照する共有アセットを展開・検証してから GPU 資源と現在の文書を置き換える。
共有アセットが欠けていれば読み込みを中止し、現在の文書を保持する。
書き込みはファイル単位の一時ファイルと置換で守る。複数ファイル全体を一括で巻き戻すトランザクションではない。

開発用オプションの `--save-project` は、拡張子が `.tgscene` ならルートへ分離保存し、`.tgproj` なら従来の埋め込み形式で書く。

## UI

アセットの帯は「アセット」1 枠に、左にルートの実フォルダのツリー、右にサブフォルダとファイルの 84px 格子を出す。
旧「レイヤーマテリアル / 境界マテリアル」のタブは廃止し、`.tglayer` / `.tgboundary` としてこの格子に並べる。
`.meta` とドットで始まる内部フォルダ（`.terrain-graph`）は隠す。
表示するのは画像 / HDRI / `.tgmat` / `.tgsky` / `.tglayer` / `.tgboundary` / `.tgscene` / 旧 `.tgproj`。

- ダブルクリックで読み込み（画像 → テクスチャとプレビュー、`.tgmat` → マテリアルと球、`.tgsky` → 天球を適用、
  `.tglayer` / `.tgboundary` → 配置データへ足して編集ウィンドウ、`.tgscene` → シーン）。
  読み込み済みのものはプレビュー・編集の窓を開くだけ。フォルダは中へ入る。
- 読み込み済みの画像・マテリアル・レイヤーマテリアル・境界マテリアルは従来のドラッグ元
  （`TG_TEXTURE` / `TG_MATERIAL` / `TG_LAYER_MATERIAL` / `TG_BOUNDARY_MATERIAL`）になる。
  レイヤーマテリアル・境界マテリアルは Road の区間の「マテリアル」「境界マテリアル」行へ落として割り当てる。
  未読み込みのファイルはパス（`TG_ASSET_PATH`）を運ぶ。割り当ての欄には落とせない（ダブルクリックで読み込んでから）。
- **ファイルのサムネイルを、一覧のフォルダか左のフォルダ階層の行へ落とすとそのフォルダへ移動する**（`io::MoveAsset`）。
  `.meta` も一緒に動かし、参照は ID で解決するので切れない。読み込み済みのものは絶対パスを付け替える
  （`Application::RelinkAssetPaths`。開いているシーン自身も同じ）。`project.tgproj` は運ばない。移動先に同名があれば動かさない。
  **フォルダも同じくドラッグで中身ごと移動する**（一覧のフォルダのサムネイル・左の階層の行のどちらからでも）。
  ルートと内部フォルダは動かさず、フォルダ自身やその配下へは落とせない。
- **名前はその場で変える**（`io::RenameAsset`）。F2 か右クリックの「名前を変更…」で、サムネイル下の名前が入力欄
  （`ui::GridCaptionInput`、名前と同じ 2 行ぶんの高さ）になる。拡張子を除いた名前を全選択で始め、Enter か外のクリックで確定、Esc で取り消す。
  拡張子は変えない。ファイルは `.meta` も新しい名前へ揃える。ルート・`project.tgproj`・内部フォルダは改名しない。
- 編集ウィンドウを開いたまま別の `.tglayer` / `.tgboundary`（読み込み済み）をクリックすると、編集の対象が切り替わる。
- 右クリック（項目）: 開く / エクスプローラで表示 / 名前を変更… / 読み込み済みならテクスチャ・マテリアルの従来メニュー、
  レイヤーマテリアル・境界マテリアルは「編集」「シーンから外す」（配置で使用中なら外さない。ファイルは残す）/ ファイルを削除…。
- 右クリック（余白）: フォルダを作成 / マテリアルを作成 / 天球を作成 / レイヤーマテリアルを作成 / 境界マテリアルを作成 / ファイルを読み込む…。
  レイヤーマテリアル・境界マテリアルは現在のシーンへ入った状態で作られ、編集ウィンドウが開く。
  **フォルダは「新しいフォルダー」で作り、そのまま名前の入力に入る**（エクスプローラと同じ）。
- 左のフォルダ階層の行も右クリックで操作する: 開く / エクスプローラで表示 / フォルダを作成（その中へ作り、一覧をそこへ移して名前の入力に入る）/
  名前を変更…（行の名前を `ui::InlineNameInput` に置き換える。ルートには出さない）。
- 「更新」で外部の変更を取り込む（ファイル監視はしない）。サムネイルも捨てて作り直す。
- フォルダ階層の幅は `settings.json` の `ui.assetFolderWidth`（拡大率を掛ける前）に覚える。

旧「テクスチャ / マテリアル / 天球」の一覧は `ウィンドウ > …（読み込み済み）` から補助ウィンドウとして出せる。
読み込み済みのものだけを対象にした操作（テクスチャの一括 ORD 割り当て、リンク切れの一括繋ぎ直しなど）はそちらに残す。

## サムネイルと履歴

未読み込みの画像・共有マテリアル・共有天球・境界マテリアルは、表示範囲から 1 フレームに 1 件ずつサムネイルを作る（`AssetThumbnailCache`）。
シーンのライブラリとは別の読み込み領域を使い、メモリには最大 128 件を保持する。画像は縦横比を保った 128px、
マテリアル・天球は既存の球、境界マテリアルは境界マスク（無ければハイト）の画像。
生成したものは `.terrain-graph/thumbnails/` へ PNG と検証用 JSON で残し、
入力ファイルと参照先（`.tglayer` → `.tgmat` → 画像のように辿る）の更新日時・サイズ・生成形式の版から有効性を判定する（`io/ThumbnailStore`）。
ディスクキャッシュは消しても再生成できる。容量の自動整理は未対応。
マテリアル・天球の生成ではルートを走査し直さない（ルートの切り替えと「更新」などの無効化のときに 1 回だけ）。
読み込んだ画像は同じフォルダの続くマテリアルで使い回し、表示中の要求を作り終えたときか 12 枚を超えたときに返す。

**レイヤーマテリアルは帯の側では描画しない**（道路の評価と描画が要る）。読み込み済みのものはシーンのサムネイル
（平面の合成結果）をそのまま出し、保存の直後にその画像を同じディスクキャッシュへ残す（`Application::PersistLayerThumbnails`）。
保存後に文書を変えたら残さない（保存したファイルと違う絵を記録しない）。未読み込みで記録の無いものは「レイヤー」の文字を出す。

シーンのサムネイルは保存時にビューポートを最大 256px へ縮小して `.terrain-graph/scene-thumbnails/` に置く。
名前は `sceneUid` から決めるので、改名・移動しても引き継ぐ。同じ保存先は ID を保ち、名前を付けて保存では新しい ID になる。
失敗してもシーン本体の保存は成功扱い。

履歴は `%LOCALAPPDATA%/road-editor/recent.json` の版 2。ルートの一覧と、ルートごとのシーンの一覧を新しい順で最大 10 件ずつ持つ。
版 1（`.tgproj` の一覧）は、所属するルートを開いたときにそのルートのシーン履歴へ移す。

## ファイルの削除（退避）

帯の「ファイルを削除…」はライブラリから外す操作とは別で、ファイル自体を `.terrain-graph/trash/DeletedAsset.../` へ移す。
対象と付随する `.meta` だけを動かし、`restore.json` に元の相対パスを記録する。復元はエクスプローラで手で戻す。

確認前にルート内のシーン・共有アセット（`.tglayer` / `.tgboundary` を含む）・旧プロジェクトを走査し、ID とパスによる参照元と、対象が参照する素材を列挙する。
読めない文書があれば検査を不完全とみなして削除を拒否する。現在のシーンに読み込まれているファイルと開いているシーンも止める。
確認後にも対象と参照関係を再検査し、変わっていれば再確認を求める。連鎖削除や参照元の書き換えはしない。

## 残る範囲

- ファイル監視、検索・種類の絞り込み、複数選択での一括移動、フォルダの削除。
- 未読み込みのアセットを割り当ての欄へ落とす（落とした時点で読み込む）。現状はダブルクリックで読み込んでからドラッグする。
- 一度も保存・読み込みしていない `.tglayer` のサムネイル（帯の側でのレイヤーの描画）。
- 形状プリセット（断面・境界条件）の共有化。現状はシーンの配置データに埋め込み。
- ごみ箱の整理・復元 UI、サムネイルのディスク容量の整理。
- 削除前の検査はルート内だけが対象。ルート外の参照元は見えない。
