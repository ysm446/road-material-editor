# goals — Road Editor の目的と完成形

作成日時: 2026-08-31 05:46
更新日時: 2026-09-06 12:06

## 目的

**Road Editor（road-editor）** は、道路と道路付属物をノードグラフで非破壊に構築し、
PBR 表示で形状と表面表現を確認する Windows 向けのメッシュベースのオーサリングツール。
ハイトマップ中心の仕様は廃止し、実寸3Dパスとメッシュを編集データの中心にする。
terrain-graph から派生し、[道路エディタ構想](../reference/road-editor-project-proposal.md)を
本プロジェクトの開発方針として採用する。

中心パスから道路面と左右境界を生成し、境界へ路肩・縁石・歩道・側溝・ガードレールを
接続する。道路幅やパスの編集が、接続した付属物と白線・汚れ・轍へ追従することを目指す。

1 unit = 1 m とし、当面は50 m以内に収まる道路と付属物の編集を想定する。
50 m四方のグリッドを寸法の目安として表示する。編集可能範囲を制限するものではない。

## 完成形

1. 中心線・縦断高さ・幅・横断勾配から独立した道路メッシュを生成する。
2. 道路面と左右境界を型付きの出力として流し、付属物の位置を接続関係から導出する。
3. 白線・汚れ・轍・補修跡を道路座標から生成し、色・粗さ・法線へ合成する。
4. 直接光・影・IBL・露出・トーンマップを使い、道路と付属物を一緒に確認する。
5. 編集用グラフを保存・再読込し、生成データを再構築できる。将来はメッシュと PBR テクスチャを書き出す。

## 重視する価値

- 長さ・幅・高さ・配置間隔はメートル。UV、破線、支柱は曲線パラメータではなく実距離を基準にする。
- 段差・輪郭・影を必要とする箇所はメッシュ、薄い表面変化は材質合成やデカールで表す。
- 道路はハイトマップと独立させ、同じ水平位置に異なる高さの面を持てる構造にする。
- 道路網のループと評価依存の DAG を区別する。ノード評価はデータを返し、描画や共有シーンを直接変更しない。
- 編集データを正とし、メッシュと GPU リソースは再生成する。段階ごとにビルド・起動・保存往復を確認する。
- 既存の PBR / RHI / ノード編集基盤を活用する。Normal の合成は接空間を揃えて RNM を使う。
- 外部素材の色空間・法線方向・チャンネル規約に合わせ、独自仕様は設計資料へ理由を残す。

## 現在地

派生元の基盤に、独立した複数メッシュの PBR 表示・保存経路を追加した段階。
道路メッシュ、道路面・左右境界の出力、路肩・白線・デカールはまだ実装していない。
到達点は [progress.md](progress.md)、開発順序は [plan.md](plan.md) に記録する。

## 非目標と後続範囲

土木設計基準への適合判定、交通シミュレーション、施工成果物は対象外。
交差点・合流・可変幅・切り土／盛り土・橋・LOD は基本の道路編集後に扱う。
汎用デカールのためだけに全面的なディファード化はしない。
Windows / DirectX 12 以外への移植、クラウド連携、メッシュのスカルプトや UV 展開は当面行わない。
