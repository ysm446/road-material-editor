# plan — Road Editor の実装方針と優先順位

作成日時: 2026-08-31 05:46
更新日時: 2026-09-08 01:44

利用者が触って評価できる状態を優先し、P4の最小区間UIを先行実装した。作成・分割・境界移動・プリセット複製と素材変更・解除を通常描画、保存、Undoへ接続。手順は [道路本体の区間材質](../reference/road-surface-editor.md)。

道路本体の区間評価を開発用プレビューに接続済み（最大3種・各4層）。帯の独立評価、混合率と公開値の補間を導入。多層材質を版18の保存と評価に統合済み。通常起動とRoadの区間編集UIへ統合済み。公開値の結線・沿道形状は後続。詳細は [配置記述](../reference/surface-layout-data.md)。

沿道1帯の断面生成と左右の仮配置UIを追加した。沿道の下地1層の材質表示・編集を追加済み。次は上層合成・変位と境界契約の解決を統合する。[形状試作の範囲](../reference/roadside-shape-prototype.md)。

道路最大3構成＋左右各2構成で、横方向の材質境界の試作を追加。両面の材質接続に加え、境界で変位を0へ減衰させる高さ接続を選択できる。白線付きの一定勾配と円弧状の道路を実機確認し、距離の丸め誤差による沿道生成失敗を修正した。右側にも対応した。左右同時接続を追加した。道路の複数プリセットとの同時接続を追加した。沿道の単純断面の幅・高さ・割当・複製UIを追加した。沿道区間の分割・削除と道路長への比例伸縮操作を追加した。パス編集時は路面・左右沿道が自動追従する。配置から共通のプリセット編集画面を分離し、沿道も最大4層のマスク・ハイト合成に対応した。プリセット用ノードグラフの第一段（素材・マスク・合成・出力、既存4層への展開、保存・Undo）を実装した。次は公開値と区間ごとの寸法上書きを結線する。縦断曲線・バンク・急カーブの検証も残る。[対応範囲と検証](../reference/lateral-material-connection.md)。

## 方針の転換

terrain-graph の地形・材質編集基盤を引き継ぎ、道路・道路付属物のオーサリングへ転換する。
[構想書](../reference/road-editor-project-proposal.md)の5段階を採用する。
侵食ノードの追加や地形 LOD より、独立した道路メッシュの生成と表示を優先する。

## 決定事項

| 項目 | 方針 |
| --- | --- |
| 名称 | road-editor / 表示名 Road Editor / 実行ファイル road_editor.exe |
| 技術 | C++20、CMake + vcpkg manifest、Windows、DX12、HLSL SM 6.6 / DXC |
| UI | Dear ImGui docking + imgui-node-editor。既存の Property* とテーマを使用 |

| 保存 | 初期段階は .tgproj / .tgmat と terrain-graph.* の形式識別子を継続。旧 .mmproj / .mmmat の読込も維持 |

道路用データを保存する段階で、形式の版・必要なら専用拡張子と移行規則を設計する。
現段階で拡張子だけを道路専用に変え、道路データが保存可能であるかのようには扱わない。

## 境界マテリアル

舗装と土の境目を画像で指定するため、独立した境界アセットの第一段を実装。沿道の片側全体へ共有アセットを割り当て、U/Vの反復マスクとハイトを路面・沿道から共通参照する。ノーマルはハイトから計算する。次は境界アセットの区間ごとの切替と専用3Dプレビュー、反復端の補正・品質調整。形状切替UIも引き続き後続に置く。現行の範囲は [境界マテリアル](../reference/boundary-materials.md)。

## レイヤーマテリアルと配置の整理

独立したレイヤーマテリアルを路面・路肩・歩道で共有する基盤を実装した。材質編集画面は合成と凹凸量を扱い、沿道の幅・高さはRoadで区間ごとに編集する。旧形式からの移行と保存・Undoを維持する。詳細は [材質アセット](../reference/layer-material-assets.md)。
次は路肩／歩道の形状切替を材質選択から独立させるUIと、異なる幅・段差の接続検証を進める。現段階の評価上限は材質ID数ではなく形状を含む構成数に依存する。

## 次の優先作業 — 道路・沿道プリセットと自動接続

路肩を全長同じ設定で押し出す方式から、ノードグラフで作るプリセットを道路沿いの区間と横の帯へ配置する方式へ移行する。
接続相手ごとのプリセットや材質合わせを要求せず、境界条件から形状・材質・変位を自動で解決する。
横方向・進行方向の変化、上がる歩道、始終端、出入口のすり付けを同じ基盤で扱う。
道路本体も新舗装→荒れた舗装→砂利道の区間を配置し、移行距離と荒れ具合の連続変化で仕上げる。
道路の形・車線は Road が保持し、路面と左右の沿道は独立した区切りを持つ。材質ごとの Road 分割は不要にする。

詳細は [道路・沿道プリセット・区間配置・自動接続への移行計画](roadside-presets.md)。P0の水平直線での最小実証を完了。4層＋4層＋歩道1層の接続、GPU負荷とサンプル点の境界誤差を確認した。詳細は [計測資料](../reference/connection-diagnostics.md)。
P0 接続の最小実証 → P1 記述と保存 → P2 二方向の接続 → P3 プリセット作成 → P4 区間操作 → P5 移行と最適化。
P1の記述と保存の基盤は第一段を実装済み。BoundaryContract・断面・安定ID・配置区間・埋込プリセット・公開値の始終端値を型として導入し、版17とUndoへ統合した。多層材質の保存と道路区間の評価を追加済み。次は公開値の結線と沿道の評価を整える。曲線と全視点での亀裂検証はP2で継続する。

この計画を R3 の路肩拡張と R5 の歩道・縁石に共通する優先基盤とする。R4 のマスクスタンプ・Crack 第二段はその後に統合する。
以下の既存ロードマップのうち、部品の手接続・端の素材一致を前提にした方針と作業順序は本節で更新する。
旧地形の撤去は progress.md のとおり完了しており、旧仕様の再導入は行わない。

#### ひび割れデカール（2026-09-07 追加）

枝分かれした割れ模様を面上の Path で表し、その各枝に帯メッシュを置く。Decal の延長として扱い、新しい描画経路は作らない。

- **形状は Path**。面上の Path は既に分岐（複数ストランド）を持て、`BuildDecal` はストランドごとに帯を出すので、枝分かれ自体は今の仕組みで描ける。足りないのは次の 4 点。
  1. **幹と枝を分ける**。ストランドを「幹（主線）」と「枝」に分類する。分類は Path 側で持つ（ストランドの属性、または幹の Path と枝の Path を別ノードにして Decal に 2 入力で渡す）。幹は不透明な帯、枝はアルファ付きの帯として別々の材質・設定を持てる。
  2. **点ごとの幅とアルファ**。幹は太く、枝先へ向かって細くする。Path の点は既に幅と強さ（マスク用）を持つので、Decal が幅を帯の幅、強さを帯のアルファとして読む選択肢を持たせる。枝は先端で幅 0・アルファ 0 へ絞り、根元は 1 から始める。帯の頂点にアルファを持たせ、材質の不透明度に掛ける。
  3. **分岐点のつなぎ**。枝の根元が幹の帯からはみ出さないよう、根元の数点を幹の幅の内側から始める。枝はアルファで溶けるので重なりは目立たない。帯同士の頂点共有はしない。
  4. **材質**。長さ方向に反復する割れ目の材質（アルファ付き、法線でくぼみ）。幅方向 0〜1 の UV はそのまま使う。幹と枝で別の材質を割り当てられる。
- **生成の補助**。手で描くのが基本だが、幹のパスから枝を生やす生成（分岐数・角度・長さのばらつき・乱数種）を Path の操作として後から足せる。生成結果は通常の点と辺になり、手で直せる。
- **マスク連携**。ひびの周りの汚れや補修跡は R4 の「マスクへのスタンプ」で道路マスク B へ書き、材質スロット 4 で塗る。帯メッシュ（割れ目そのもの）とマスク（周辺の変色）の二段構え。
- 完了条件: 幹 1 本と枝 3〜5 本のひびを描き、幹は不透明、枝は根元から先端へ細く薄くなり、分岐点に隙間や浮きが出ない。急カーブ上でも帯が路面から離れない。

状態（2026-09-07）: **自動配置の Crack ノード**を第一段として実装。乱数種と密度で 3〜6 m の塊を置き、幹（ランダムウォーク）と枝（30〜70°、先端で幅 0）、
半分の枝に子枝 1 本。向き（縦 / 横 / 混合）、横位置（一様 / 轍寄り / 端寄り）。帯は Decal と同じ仕組み（`AppendSurfaceStrip`）で、幅の先細りのみ。
手描きは面上の Path ＋ Decal のまま。未実装: 頂点アルファ（枝の先薄れ）、枝用の別材質、生成結果を Path へ書き出す「Path へ変換」。

## ハイトマップ仕様と旧ノードの撤去

ハイトマップ中心の仕様は廃止する。道路は実寸の3Dパスとメッシュを正とし、地形の Height や
正規化 UV に依存せず生成できるようにする。地形を扱う場合も将来の任意入力として検討する。

| 対象 | 扱い |
| --- | --- |
| ノード UI、リンク検証、コピー／貼り付け、アンドゥ | 再利用。スナップショット等を新しいノード設定へ対応させる |
| Path と Mask Path | 既存の地形 UV 前提を廃止。曲線処理を参考に実寸3Dパスへ再設計。パスマスクは用途を再検討 |
| Heightmap、Blur、侵食、Sediment、Snow、Crumbling、River、地形上の Scatter | メッシュ経路へ移行後に撤去。Scatter のインスタンス配置は別機能として設計 |
| 地形由来の Mask Height / Slope / Curvature / Fluvial | 撤去。メッシュ属性から必要になれば別途設計する |
| Surface / Shape / Liquid、画像・ノイズ・マスク加工 | 旧ノードをそのまま温存せず、道路材質に必要な処理を選別して再利用 |
| PBR、テクスチャ入出力、IBL、RHI | 再利用。ハイトマップ合成器と描画経路の結合は解消する |

撤去は次の順に行う。

1. R1 でハイトマップ合成に依存しないメッシュの表示経路を作る。
2. R2 で3Dパスと道路の評価・編集・保存・アンドゥを一巡させる。
3. 新規プロジェクトをメッシュグラフへ切り替え、旧ファイルの明示的な取り込み／拒否方針を実装する。
4. 不要ノードの登録・UI・保存・評価・専用シェーダ・テストを依存単位で撤去する。
   テクスチャ素材と PBR の共有部分は維持し、削除後にビルド・保存往復・描画を確認する。

今回の方針整理ではノードの一括削除は行わない。旧ノードの恒久的な互換実行も目標にしない。

## 道路材質のレイヤー構造（2026-09-07 決定）

最終出力はハイエンドのゲームグラフィックを想定し、道路 1 本を「タイル材質（最大 4 種）＋ 道路空間のブレンドマスク ＋ 帯メッシュ」で表す。
ユニークテクスチャを道路ごとに焼く方式は取らず、必要になれば最終出力の選択肢として後から足す。

| 段 | 内容 | マスク | 出力 |
| --- | --- | --- | --- |
| 1 | 下地アスファルト | なし（タイル材質を低周波ノイズで混ぜる） | タイル材質 |
| 2 | 轍（磨かれた部分） | 横位置の断面プロファイル × 長さ方向ノイズ。必要なら数 mm の凹み | 道路マスク R |
| 3 | 路肩側の汚れ・砂利 | 道路端からの距離で減衰 × ノイズ | 道路マスク G |
| 4 | ひび・補修・染み | 長さ方向ノイズのしきい値。まとまった形は R4 のスプラインデカール | 道路マスク B ＋ デカール |
| 5 | 白線・矢印・停止線 | 帯メッシュ（実装済み）。塗料材質に摩耗マスク | 別メッシュ |
| 6 | 濡れ・水たまり | ハイトの低い所に水位（Liquid の考え方） | 道路マスク A |

- 材質の合成はタイル 1 枚に対して行う既存の合成器を使い、道路に沿って変わるものは道路空間（横位置 × 実距離）の
  低解像度マスク（横 256 px、長さ 1 m あたり約 20 px）で決める。マスクは Road Mask ノードが作り、Road のマスク入力へ繋ぐ。
- Road の材質入力を 4 スロットにし、描画時に道路マスクの重みとハイトでブレンドする（規則は `HeightBlendWeight` と同じ）。
  変位はブレンド後のハイト。白線の押し出しも同じブレンドを使う。
- タイル材質の座標は Road ごとに「道路に沿う（道路 UV）」と「ワールド XZ 平面」を選べるようにする。路肩や地面と地続きに
  したい層はワールド XZ、方向性のある層（轍、摩耗）は道路 UV。マスクと白線は常に道路空間。
- 書き出しは「メッシュ（位置・法線・接線・道路 UV）＋ タイル材質の PBR セット ＋ 道路マスク PNG」。チャンネルの意味を固定して文書化する。
- 実装順: (1) Road Mask ノードと道路マスクの評価、(2) Road の材質スロット化とブレンド描画、(3) テクスチャ座標の選択、(4) R4 デカール。

## 付属部品のノード分割

Roadの左右境界Pathへ、路肩・縁石・歩道を別ノードとして接続する。幅・断面・材質を部品側で管理し、外側境界を次の部品へ渡す。今回のRoadは境界出力まで実装した。

## 材質編集UIの更新

ユーザーの操作方針に合わせ、レイヤーマテリアルは正方形の変位プレビューとレイヤー一覧を基本にする。素材と白黒マスクのサムネールを並べる。第一段は既存プリセットを専用ウインドウで編集する。次に材質を断面から独立したアセットへ抽出し、沿道プリセットから参照する。複雑なマスクのノード編集は必要な箇所に限定して後続で検討する。
