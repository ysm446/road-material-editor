# plan — Road Editor の実装方針と優先順位

作成日時: 2026-08-31 05:46
更新日時: 2026-09-07 05:11

## 方針の転換

terrain-graph の地形・材質編集基盤を引き継ぎ、道路・道路付属物のオーサリングへ転換する。
[構想書](../reference/road-editor-project-proposal.md)の5段階を採用する。
侵食ノードの追加や地形 LOD より、独立した道路メッシュの生成と表示を優先する。

## 決定事項

| 項目 | 方針 |
| --- | --- |
| 名称 | road-editor / 表示名 Road Editor / 実行ファイル road_editor.exe |
| 技術 | C++20、CMake + vcpkg manifest、Windows、DX12、HLSL SM 6.6 / DXC |
| UI | Dear ImGui docking + imgui-node-editor。既存の Property* とテーマを使用 |
| 描画 | 既存フォワード PBR を維持。白線は照明前の路面マテリアル合成から始める |
| 単位 | 道路の3D座標・幅・高さ・距離・間隔は m。地形の正規化 Height / UV に依存しない |
| 保存 | 初期段階は .tgproj / .tgmat と terrain-graph.* の形式識別子を継続。旧 .mmproj / .mmmat の読込も維持 |
| アプリ設定 | %LOCALAPPDATA%/road-editor/。レイアウトは road_editor_imgui.ini。派生元とは別管理 |
| 内部識別子 | 名前空間 tg、TG_* を継続。アイコンは Road Editor 専用。名称変更だけの全面的なコード置換は行わない |

道路用データを保存する段階で、形式の版・必要なら専用拡張子と移行規則を設計する。
現段階で拡張子だけを道路専用に変え、道路データが保存可能であるかのようには扱わない。

## 実装順序と完了条件

### R1 — 派生プロジェクトの起動とシーン基盤

- 名称、ビルドターゲット、設定保存先、ドキュメントを更新する。
- 既存ノード編集・PBR 表示・保存再読込を新しいアプリとして確認する。
- ハイトマップ合成に依存しない複数メッシュの最小シーンを追加する。
- ノード出力からシーンを構築し、GPU への反映・状態遷移・遅延破棄を描画側へ集約する。

完了条件: 新名称で起動し、保存往復でき、複数の独立メッシュを PBR 表示できる。

状態: 完了。

### R2 — 中心パスから道路を生成

- 分岐のないパスをサンプリングし、一定幅の道路メッシュを生成する。
- 実距離 UV、RoadSurface、左右境界 Path を出力する。形状生成は純粋なデータ処理とする。
- 設定の保存、リンク検証、キャッシュ更新、アンドゥへ統合する。

完了条件: 直線・曲線・緩い縦断を表示し、パスと幅の変更に道路面・境界が追従する。
制御点の密度が変わってもテクスチャの反復長が変わらない。

状態: ほぼ完了。実寸Pathの3次元編集、一定幅の道路生成、左右境界、実距離UV、Material入力による道路UVでの材質表示、
縦断曲線（縦断ポイント）とバンク角（設計速度による自動・回転ギズモによる手動）、保存、リンク検証、キャッシュ更新、
アンドゥまで実装済み。旧Pathは明示的に変換できる。遠く離れた区間同士の自己交差検査が残る。

### R3 — 路肩と白線

- 左右境界へ路肩を接続し、路肩の外側境界を次の部品へ出力する。
- 道路座標で実線・破線を合成し、塗料の色・粗さ・下地の細部を制御する。

完了条件: 幅の変更に路肩・白線が追従し、白線が路面と同じ照明・影を受ける。

状態: 着手中。白線の中央線・外側線を帯ポリゴンで実装済み。路肩ノードと破線が残る。

### R4 — スプラインデカール

任意幅・反復長・横オフセットの帯で汚れ・轍・補修跡を道路面へ配置する。
帯の形状と材質合成を分離し、優先度と端のフェザーを持つ。
完了条件: 急カーブ、継ぎ目、重複、遠景を確認し、浮き・二重合成・ちらつきを評価する。

状態: 着手済み。面上のパス（Path の Surface 入力）と Decal ノード（帯メッシュ）を実装。マスクへのスタンプと評価（急カーブ・継ぎ目・重複・遠景）は未実施。

### R5 — 付属物と汎用デカール

縁石・側溝の断面生成、支柱・標識・ガードレールの生成／インスタンス配置を追加する。
任意物体への投影が必要になった段階で DBuffer、対象制限、投影深度、法線合成を設計する。
完了条件: 境界の移動に付属物が追従し、実距離で配置でき、投影先を限定できる。

状態: 未着手。

### 後続

交差点・合流・可変幅・切り土／盛り土・橋・LOD・メッシュ書き出し。
交差点は帯の重ね合わせではなく接合形状と車線表示を設計する。
地形との依存は「入力地形 → 道路 → 加工後地形」の一方向とする。

## 次の設計で確定すること

- 当面の目安は50 m以内。近接精度と縦断曲線の詳細な編集方法を詰める。
- Path / RoadSurface / CrossSection / Mesh / Material / DecalSet / InstanceSet の型と所有権。
- シーンのメッシュ／インスタンスとノード出力の対応、区間キャッシュと更新範囲。
- 道路データの保存形式、地形・素材の取り込み、最初のメッシュ書き出し形式。

## 見つけている課題（未着手）

- 法線マップを持つ材質では、起伏の強さが Height にだけ効く。法線の早期 return が原因。
- 起動直後の MaterialThumbnail / TexturePreview で GPU barrier layout 警告の記録がある。
  派生元では素材付きプロジェクトの読込直後に記録されている。MaterialThumbnail の
  UAV / COMMON 状態遷移を確認する。今回の最小グラフでは未再現。
- マスクは DAG + キャッシュだが材質合成は線形。汎用の幾何評価器がある前提にしない。

## ハイトマップ仕様と旧ノードの撤去

ハイトマップ中心の仕様は廃止する。道路は実寸の3Dパスとメッシュを正とし、地形の Height や
正規化 UV に依存せず生成できるようにする。地形を扱う場合も将来の任意入力として検討する。

| 対象 | 扱い |
| --- | --- |
| ノード UI、リンク検証、コピー／貼り付け、アンドゥ | 再利用。スナップショット等を新しいノード設定へ対応させる |
| Path と Mask Path | 既存の地形 UV 前提を廃止。曲線処理を参考に実寸3Dパスへ再設計。パスマスクは用途を再検討 |
| Heightmap、Blur、侵食、Sediment、Snow、Crumbling、River、地形上の Scatter | メッシュ経路へ移行後に撤去。Scatter のインスタンス配置は別機能として設計 |
| 地形由来の Mask Height / Slope / Curvature / Fluvial | 撤去。メッシュ属性から必要になれば別途設計する |
| Surface / Shape / Liquid、画像・ノイズ・マスク加工 | 旧ノードをそのまま温存せず、道路材質に必要な処理を選別して再利用 |
| PBR、テクスチャ入出力、IBL、RHI | 再利用。ハイトマップ合成器と描画経路の結合は解消する |

撤去は次の順に行う。

1. R1 でハイトマップ合成に依存しないメッシュの表示経路を作る。
2. R2 で3Dパスと道路の評価・編集・保存・アンドゥを一巡させる。
3. 新規プロジェクトをメッシュグラフへ切り替え、旧ファイルの明示的な取り込み／拒否方針を実装する。
4. 不要ノードの登録・UI・保存・評価・専用シェーダ・テストを依存単位で撤去する。
   テクスチャ素材と PBR の共有部分は維持し、削除後にビルド・保存往復・描画を確認する。

今回の方針整理ではノードの一括削除は行わない。旧ノードの恒久的な互換実行も目標にしない。

## 道路材質のレイヤー構造（2026-09-07 決定）

最終出力はハイエンドのゲームグラフィックを想定し、道路 1 本を「タイル材質（最大 4 種）＋ 道路空間のブレンドマスク ＋ 帯メッシュ」で表す。
ユニークテクスチャを道路ごとに焼く方式は取らず、必要になれば最終出力の選択肢として後から足す。

| 段 | 内容 | マスク | 出力 |
| --- | --- | --- | --- |
| 1 | 下地アスファルト | なし（タイル材質を低周波ノイズで混ぜる） | タイル材質 |
| 2 | 轍（磨かれた部分） | 横位置の断面プロファイル × 長さ方向ノイズ。必要なら数 mm の凹み | 道路マスク R |
| 3 | 路肩側の汚れ・砂利 | 道路端からの距離で減衰 × ノイズ | 道路マスク G |
| 4 | ひび・補修・染み | 長さ方向ノイズのしきい値。まとまった形は R4 のスプラインデカール | 道路マスク B ＋ デカール |
| 5 | 白線・矢印・停止線 | 帯メッシュ（実装済み）。塗料材質に摩耗マスク | 別メッシュ |
| 6 | 濡れ・水たまり | ハイトの低い所に水位（Liquid の考え方） | 道路マスク A |

- 材質の合成はタイル 1 枚に対して行う既存の合成器を使い、道路に沿って変わるものは道路空間（横位置 × 実距離）の
  低解像度マスク（横 256 px、長さ 1 m あたり約 20 px）で決める。マスクは Road Mask ノードが作り、Road のマスク入力へ繋ぐ。
- Road の材質入力を 4 スロットにし、描画時に道路マスクの重みとハイトでブレンドする（規則は `HeightBlendWeight` と同じ）。
  変位はブレンド後のハイト。白線の押し出しも同じブレンドを使う。
- タイル材質の座標は Road ごとに「道路に沿う（道路 UV）」と「ワールド XZ 平面」を選べるようにする。路肩や地面と地続きに
  したい層はワールド XZ、方向性のある層（轍、摩耗）は道路 UV。マスクと白線は常に道路空間。
- 書き出しは「メッシュ（位置・法線・接線・道路 UV）＋ タイル材質の PBR セット ＋ 道路マスク PNG」。チャンネルの意味を固定して文書化する。
- 実装順: (1) Road Mask ノードと道路マスクの評価、(2) Road の材質スロット化とブレンド描画、(3) テクスチャ座標の選択、(4) R4 デカール。

## 付属部品のノード分割

Roadの左右境界Pathへ、路肩・縁石・歩道を別ノードとして接続する。幅・断面・材質を部品側で管理し、外側境界を次の部品へ渡す。今回のRoadは境界出力まで実装した。
