# カスケードシャドウマップ

作成日時: 2026-09-07 21:22
更新日時: 2026-09-07 21:33

## 設定

「プレビュー設定 → 影」の方式で1枚／4カスケードを選ぶ。既定は4カスケード。1枚方式はシーン包囲球全体を覆うカメラ非依存の投影とし、テクスチャ確保と影描画も1枚分に減らす。方式は `preview.shadowCascadeCount`（1／4）へ保存し、省略・不正値は4を使う。解像度1024／2048／4096は1枚あたりの寸法。従来の `preview.shadowResolution` をそのまま保存・読込し、旧ファイルは2048で開く。

## 分割と投影

カメラ前方距離で4分割する。カメラのクリップ範囲とシーンの包囲球から有効距離を決め、対数分割70%・等間隔分割30%を混ぜる。次のカスケードは直前区間の末尾10%を重複して覆い、ピクセルシェーダで滑らかに混合する。

各区間の視錐台8隅の包囲球で正方形の投影幅を決める。幅を1/16 m単位へ切り上げ、PCFと位置丸めの余白を足す。光源座標系を原点に固定し、投影中心XYをテクセルに揃える。分割距離が変わるズームやパンによる投影サイズの変化まで完全に固定する方式ではない。

深度はシーンの包囲球を覆い、最大変位量も余白に加える。画面外でも、見えている面に影を落とす物体を深度範囲から除かない。3×3 PCFを使用し、バイアスは1.5テクセル相当を基準に面の傾きに応じて増やす。テセレーションの分割基準はすべて本描画のカメラを使う。

## リソースと負荷

選択した方式に応じて独立したR32_TYPELESSテクスチャ1枚または4枚にDSVとSRVを持つ。方式・解像度の交換時は必要な枚数の確保成功後に旧マップを遅延解放する。失敗時は旧セットを保持する。各パスにPIXマーカーを付け、深度書込からピクセルシェーダ読込へ状態を遷移させる。

カスケードの選択はピクセルごとに異なるため、ディスクリプタヒープの参照には `NonUniformResourceIndex` を使用する。

解像度2048では深度本体が計64 MiB、4096では計256 MiB（アロケータの余白等を除く）。影の描画は最大4回になる。現段階ではカスケードごとのオブジェクト除外、更新キャッシュは未実装。1枚方式の深度本体は2048で16 MiB、4096で64 MiB。

## 検証と残る範囲

CPUテストは分割距離の単調性、横長・縦長画面の視錐台包含、重複領域、真上・真下の光、シーン全体のZ範囲、解像度に応じたバイアス、微小パン時のテクセル整列を対象とする。DXCでVsMain／VsControl／PsMain／HsMain／DsMainをコンパイルする。

Debug／Releaseのビルドと全テスト、上記5エントリポイントのDXCコンパイルが成功。DebugのGPU検証を有効にした描画が完了し、ログに警告・エラーがないことと画像を確認した。

実機資料は `data/connection-prototype/csm-*`。Releaseで近景・遠景の歩道の影と4096の設定を確認。全光源角度、長時間のカメラ移動、カスケード切替境界の全画素比較、負荷の定量比較、確保失敗の再現は未検証。
