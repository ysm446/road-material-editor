# 接続試作のGPU計測と境界検査

作成日時: 2026-09-07 15:51
更新日時: 2026-09-07 15:54

## 計測の範囲

`--measure-preview` は開発用の計測を有効にする。通常の道路にも接続試作にも使える。保存するプロジェクトや表示UIは変更しない。

- GPU時間: 直接描画キューのタイムスタンプを使い、影・道路・背景・トーンマップ・表示グリッドを含むプレビュー描画を測る。ImGui、Present、素材読込、CPU生成、別キューで走る材質タイルの再評価、継ぎ目検査自体は含まない。
- 材質評価中と描画のないフレームを除外し、最初の有効8フレームを捨てる。その後30フレームずつ平均・最小・最大をログへ出す。
- VRAM: 同時点のプロセス全体の使用量とD3D12MA確保量を記録する。素材画像・空・描画ターゲット等を含み、道路だけの使用量ではない。検査用の一時リソースは読み戻し後に遅延解放する。
- CPU時間: グラフ評価とメッシュ／マスク生成の所要時間。GPU転送・材質タイル評価は含まない。

フレームごとのクエリと読み戻し領域を分け、完了フェンスを確認してからCPUで読む。計測のための同期待機は追加しない。
プレビューサイズ・生成シーン・材質解像度の変更では集計をリセットする。材質変更時も検査を無効化してやり直す。
測定は固定カメラ・固定設定で行う。操作中のログを単一条件のベンチマークと扱わない。

## 継ぎ目の検査方法

生成時に隣接する二辺の頂点番号を記録する。位置の一致で辺を探す方式ではないため、ずれた辺も検査対象に残る。
横方向の地表／立ち上がり／天端に加え、目地などの長さ方向の硬い法線境界を記録する。

1. 両側それぞれの位置・道路UV・法線をGPUへ渡す。
2. 各辺を端点込み33点で補間し、描画用の `ApplyDisplacement` をコンピュートシェーダーから呼ぶ。
3. 両側の変位後の3D位置差を読み戻す。0.1 mm超の点数、最大差、非有限値を集計する。
4. 確認用に一辺を追加し、入力の片側をY方向へ1 mmずらす。33点すべてで0.8〜1.2 mmの差を検出することを要求する。また出力にも既知の1 mm差を持たせ、未実行やゼロ埋めを合格と誤認しない。

最大8,192辺を対象とし、それを超える場合は全体から等間隔に抽出する。実際の対象数と総辺数をログへ記録する。
24 mの標準試作は全6,753辺・222,849点、50 mは14,235辺中8,192辺・270,336点を検査する。確認用の33点は地形の誤差集計に含めない。

これはサンプル点での変位関数と入力の整合性を検証する。ハードウェアテセレーターが実際に生成した全頂点や、ラスタライズ後の隙間を読み戻す検査ではない。
影と本描画での分割整合、辺の間の全位置、全視点、曲線・勾配・バンクまで保証する結果ではない。目視確認と併用する。

## 再実行

素材とIDは手元のものへ置き換える。DebugはGPUベース検証と最適化なしシェーダーの影響を受けるため、速度の比較にはReleaseを使う。

```powershell
$sourceProject = 'path/to/source.tgproj'
$testProject = 'data/connection-prototype/measure-50m.tgproj'
$asphaltId = 4
$gravelId = 2
python tools/make_connection_prototype.py $sourceProject $testProject --asphalt $asphaltId --gravel $gravelId --layered --length 50

$appExe = 'build/bin/Release/road_editor.exe'
$baselineShot = 'data/connection-prototype/baseline.png'
$connectionShot = 'data/connection-prototype/connection.png'
& $appExe --project $testProject --measure-preview --screenshot $baselineShot --screenshot-frame 96
& $appExe --project $testProject --connection-prototype 10 30 5 --measure-preview --screenshot $connectionShot --screenshot-frame 96
```

同じPC・ビューポート解像度・カメラ・材質解像度・テセレーション設定で、一つずつ実行する。
起動時間をGPUフレーム時間として扱わない。通常道路と試作では描画面積・三角形数も異なるため、差は材質合成だけのコストではない。

## 実測結果

測定日: 2026-09-07。GPU: NVIDIA RTX PRO 5000 Blackwell。1168×544、材質1024、テセレーション上限16・目標8 px、DOFなし、生成コピーの固定カメラ。
Releaseの50 m道路を一つずつ起動し、それぞれ30フレーム×2区間を記録した。資料は `data/connection-prototype/final-*.log` と同名のPNG。

| 対象 | GPU平均（2区間） | CPU生成（1回） | 頂点 / 三角形 | VRAM使用量 / D3D12MA確保量 |
| --- | --- | --- | --- | --- |
| 通常道路4層 | 0.037 / 0.040 ms | 27.90 ms | 357 / 600 | 910,585,856 / 769,458,176 bytes |
| 接続試作4層＋4層＋歩道1層 | 0.663 / 0.617 ms | 72.14 ms | 29,216 / 27,224 | 978,083,840 / 859,521,024 bytes |

これはこの視点・素材・GPUの観測値であり、全環境での速度の保証や上限ではない。50 mの検査は270,336点で最大差0.000000 mm、0.1 mm超0点、非有限値／確認値の失敗0件。

Debugの24 m近景も検査し、全6,753辺・222,849点で最大差0.000000 mm、失敗0件だった。GPU平均2.642 / 2.635 msはGPUベース検証を含むため上表と比較しない。
歩道Surfaceに砂利のハイトを仮適用し、立ち上がりにも凹凸がある追加条件でも222,849点の検査が通った（`final-rough-step`）。仮歩道の既定素材は変更していない。
最終検証は入力側の1 mmずれを含む33点の確認用辺も検出できた。全起動ログに警告・エラー無し。

Debug / Releaseのビルドと全CPUテスト、検査CSと描画DSのDXCコンパイルが成功。通常道路・接続試作・凹凸付き歩道の画像を目視確認した。
P0の固定シーンでの技術的成立を確認したため、次はP1の型・保存・Undoへ進む。曲線・区間端・全視点でのテセレーション亀裂の検証はP2へ引き継ぐ。
