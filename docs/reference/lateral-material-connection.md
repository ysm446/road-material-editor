# 道路と沿道の横方向の材質接続 — 試作

作成日時: 2026-09-07 18:27
更新日時: 2026-09-07 19:16

## 操作

検証用Release実行ファイルは `build/bin/Release/road_editor_connections.exe`。
通常のRelease実行ファイルが起動中で上書きできなかったため、別名へ出力した。
Roadを選び「沿道形状（試作） → 横接続を試す」をオンにする。「形状を表示」も自動的にオンになる。
既存の路肩→歩道の仮配置を使える。材質は「沿道の下地材質」で指定する。

表示モードだけの切替で、保存データ・Undo履歴は変更しない。再起動時はオフ。
オフにすると独立した道路・沿道の材質評価へ戻る。

## 対応範囲

道路側最大3種類の材質構成（各4層は使用可）、左右各1帯・それぞれ最大2プリセット（各下地1層）。
沿道各3プリセット・上層合成は後続。条件に合わなければ接続せず、理由と元の独立表示を残す。

道路端の両側に、沿道プリセットの内端BoundaryContractから移行範囲を作る。
Blendでは道路側と沿道側が同じ物理座標・区間の種・材質比率を使う。
境界を実距離の波で揺らし、道路と路肩の材質が互いの側へ入り込む。色・粗さ・法線を既存PBR/RNMで合成する。
KeepStep・Fixed・輪郭保持では、そのプリセットの材質を道路へ滲ませない。
歩道への進行方向の移行中も、路肩成分の馴染ませと歩道成分の輪郭保持を別々に評価する。

初期状態では材質比較のためハイト変位を停止する。「変位もつなぐ」で道路と沿道の変位を有効化できる。
境界の両側最大0.5 mで変位を滑らかに0へ戻し、共通の基準高さへ接続する。狭い面では幅の半分までに制限する。
変位方向は世界Yに統一し、歩道の断面段差を保持する。境界まで元の微細な凹凸を維持する方式ではない。
沿道の変位量は「沿道の下地材質 → 凹凸の高さ」で設定する。
白線・Decalなどの道路変位参照もこの道路を使う。形状の段差・縦断はそのまま。
境界で非ゼロの変位高さを共有する処理、道路側も含む境界契約の相互解決、同じ側の複数の横帯は未実装。
稜線の法線や断面勾配による陰影差は残る。全視点・急カーブで亀裂がないことを保証する段階ではない。

Releaseの実クリックで「変位もつなぐ」を有効化し、以下を確認した。

## 右側への拡張（2026-09-07 18:52）

片側だけに沿道がある場合はその側を自動で接続する。両側にある場合は「配置する側」を接続対象とし、反対側は独立表示する。左右同時の接続は未対応。
右接続では道路の共通幅座標を反転し、各素材の座標と接線法線の向きを補正する。道路の模様と白線の変位参照位置は維持する。GPU定数は既存のUVフラグの追加ビットを使い、サイズを変更しない。

Debug / 別名Releaseのビルドと全CPUテスト、DXCのVS/PS/HS/DSコンパイルが成功。右側の白線付き円弧状道路と一定勾配で、変位接続の実クリックとUI画像を確認した。画像範囲で境界の開口は見られず、歩道の段差を保持。ログに警告・エラー無し。資料は `data/connection-prototype/right-check-{curve,slope}.tgproj` / `.png` / `.log`。両側がある場合の選択切替の実操作、縦断曲線・バンク・全視点とGPU誤差計測は未検証。

## 左右同時接続（2026-09-07 19:04）

「横接続を試す」は存在する左右の沿道をまとめて接続する。「配置する側」は編集対象だけを切り替える。道路1構成＋左右各2構成、合計5構成まで対応する。左右で区切りと材質を別々に指定できる。

道路・左沿道・右沿道・白線を、右外端から左外端までの共通実距離座標へ揃える。左右の材質マスクを共通解像度へ再サンプルし、RGBAの4成分へ格納する。残りを道路の寄与として評価する。左右それぞれの基準境界で変位を0へ減衰させる。歩道成分は面ごとに保持する。

どちらかが接続条件を満たさない場合は両側の接続を取り消し、理由を表示して独立表示へ戻す。材質評価専用データとGPUリソースは既存の管理経路を使う。保存形式変更なし。

Debug / 別名Releaseビルド・全CPUテスト、DXCのVS/PS/HS/DSコンパイルが成功。左右で切替位置が異なる（左12 m・右8 m）白線付き24 m道路をReleaseで実クリックし、円弧状道路と一定勾配のUI画像を確認した。画像範囲で両境界の開口は見られず、白線と歩道段差を保持。起動ログに警告・エラー無し。検証資料は `data/connection-prototype/both-check-{curve,slope}.tgproj` / `.png` / `.log`。縦断曲線・バンク・急カーブ・全視点、GPU誤差計測と負荷比較は未検証。Debug版の左右同時描画とRelease版の従来の左片側描画も再確認し、両ログに警告・エラー無し。

## 道路の区間変化との統合（2026-09-07 19:14）

道路最大3構成（各4層）と左右各2構成（下地1層）を同時に接続する。片側だけの接続にも対応する。道路の区切りを沿道の区切りに合わせる必要はない。

沿道との横方向の混合率を先に求め、残った道路成分を既存の1次元区間マスクで3構成へ分配する。最大7構成のPBR/RNMと変位を同じ重みで評価する。道路各構成のUV・マスク・変位量を保持する。白線は道路と同じ評価を参照する。区間マスクと追加素材は既存の評価専用メッシュ・GPU寿命管理へ載せる。保存形式変更なし。

現在は追加素材の評価データを複製しており、キャッシュ共用と負荷最適化は後続。

Debug / 別名Releaseのビルドと全CPUテスト、DXCのVS/PS/HS/DSコンパイルが成功。道路区間マスクの保持、追加プリセットのUV・変位量、片側時の未使用成分、不正参照の拒否をテストした。Releaseで道路の切替6 m・16 m、左沿道12 m・右沿道8 mの白線付き道路を実クリックし、円弧状道路・一定勾配・右片側接続を目視した。確認画像では路面の材質移行と歩道段差を保ち、境界の開口は見られない。ログに警告・エラー無し。資料は `data/connection-prototype/multi-check-{curve,slope,right}.tgproj` / `.png` / `.log`。今回のDebug実機描画、縦断曲線・バンク・全視点、GPU誤差・負荷計測は未検証。
