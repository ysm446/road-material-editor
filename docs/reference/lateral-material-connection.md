# 道路と沿道の横方向の材質接続 — 試作

作成日時: 2026-09-07 18:27
更新日時: 2026-09-07 18:54

## 操作

検証用Release実行ファイルは `build/bin/Release/road_editor_connections.exe`。
通常のRelease実行ファイルが起動中で上書きできなかったため、別名へ出力した。
Roadを選び「沿道形状（試作） → 横接続を試す」をオンにする。「形状を表示」も自動的にオンになる。
既存の路肩→歩道の仮配置を使える。材質は「沿道の下地材質」で指定する。

表示モードだけの切替で、保存データ・Undo履歴は変更しない。再起動時はオフ。
オフにすると独立した道路・沿道の材質評価へ戻る。

## 対応範囲

道路側1種類の材質構成（内部の4層は使用可）、左右いずれか1帯・最大2プリセット（各下地1層）。
左右同時接続・道路の複数プリセット・沿道3プリセットは後続。条件に合わなければ接続せず、理由と元の独立表示を残す。

道路端の両側に、沿道プリセットの内端BoundaryContractから移行範囲を作る。
Blendでは道路側と沿道側が同じ物理座標・区間の種・材質比率を使う。
境界を実距離の波で揺らし、道路と路肩の材質が互いの側へ入り込む。色・粗さ・法線を既存PBR/RNMで合成する。
KeepStep・Fixed・輪郭保持では、そのプリセットの材質を道路へ滲ませない。
歩道への進行方向の移行中も、路肩成分の馴染ませと歩道成分の輪郭保持を別々に評価する。

初期状態では材質比較のためハイト変位を停止する。「変位もつなぐ」で道路と沿道の変位を有効化できる。
境界の両側最大0.5 mで変位を滑らかに0へ戻し、共通の基準高さへ接続する。狭い面では幅の半分までに制限する。
変位方向は世界Yに統一し、歩道の断面段差を保持する。境界まで元の微細な凹凸を維持する方式ではない。
沿道の変位量は「沿道の下地材質 → 凹凸の高さ」で設定する。
白線・Decalなどの道路変位参照もこの道路を使う。形状の段差・縦断はそのまま。
境界で非ゼロの変位高さを共有する処理、道路側も含む境界契約の相互解決、複数の横帯、左右同時接続は未実装。
稜線の法線や断面勾配による陰影差は残る。全視点・急カーブで亀裂がないことを保証する段階ではない。

## 検証

Debugと別名Releaseをビルドし、全CPUテストを実行。
Blend区間の両面のマスク値一致、境界での双方の寄与、歩道の材質保持、変位停止、
白線の形状と参照、UV軸の入替、不対応入力時のシーン保持を確認。
Releaseで「横接続を試す」を実クリックし、独立表示との比較画像を確認した。
表示切替後はdirty=0・Undo=0。起動ログに警告・エラー無し。

試用ファイル: `data/connection-prototype/lateral-material-fixture.tgproj`
比較画像: `lateral-material-connected.png` / `lateral-material-separate.png`（同じフォルダ）。
実機で確認したのは水平直線の道路。曲線と白線付きの接続描画、切替を連続で繰り返す操作は今回未検証。

変位接続の追加後もDebug / Releaseビルド・全CPUテストとDXCコンパイルが成功。
共通の変位方向・境界位置・減衰幅、プリセット変位量、白線の実距離UV変換、不正値の拒否を検証した。
Releaseで変位接続を実クリックし、道路0.15 m・砂利0.30 mの設定を低い視点で確認。
画像は `data/connection-prototype/lateral-height-on.png` / `lateral-height-close.png`。
この画像範囲では境界の開口は見られず、歩道の段差を保持している。曲線・白線付きの実機描画とGPUでの境界誤差計測は未検証。

## 曲線・坂道・白線の追加検証（2026-09-07 18:46）

曲線・坂道で道路格子と沿道の等間隔点が丸め誤差で重複し、沿道生成が失敗する問題を修正。距離を道路範囲に収め、10 μm以内の点を統合する。回帰テストを追加し、Debug / 別名Releaseのビルドと全テストが成功。

Releaseの実クリックで「変位もつなぐ」を有効化し、以下を確認した。

- 上り坂: 長さ24 m、高低差2.4 m、白線付き。
- 円弧状道路: 約0.9 radの円弧を24線分で近似、長さ24 m、白線付き。
- 道路変位0.15 m、砂利変位0.30 m。路肩から高さ15 cmの歩道へ移行。

画像範囲では境界の開口や白線の大きな浮き・埋まりは見られず、段差を保持している。起動ログに警告・エラー無し。
資料は `data/connection-prototype/lateral-check-{slope,curve}.tgproj` と `lateral-check-{slope,curve}-fixed.png` / `.log`。
縦断曲線・バンク・急カーブ・全視点での確認とGPU誤差計測は後続。

## 右側への拡張（2026-09-07 18:52）

片側だけに沿道がある場合はその側を自動で接続する。両側にある場合は「配置する側」を接続対象とし、反対側は独立表示する。左右同時の接続は未対応。
右接続では道路の共通幅座標を反転し、各素材の座標と接線法線の向きを補正する。道路の模様と白線の変位参照位置は維持する。GPU定数は既存のUVフラグの追加ビットを使い、サイズを変更しない。

Debug / 別名Releaseのビルドと全CPUテスト、DXCのVS/PS/HS/DSコンパイルが成功。右側の白線付き円弧状道路と一定勾配で、変位接続の実クリックとUI画像を確認した。画像範囲で境界の開口は見られず、歩道の段差を保持。ログに警告・エラー無し。資料は `data/connection-prototype/right-check-{curve,slope}.tgproj` / `.png` / `.log`。両側がある場合の選択切替の実操作、縦断曲線・バンク・全視点とGPU誤差計測は未検証。
