# プロジェクトレビューとクリーンナップ

作成日時: 2026-09-08 04:15
更新日時: 2026-09-08 04:18

## 対象と判断

計画・進捗、CMake、区間編集と材質参照、保存、Undo、GPUの転送・遅延解放を中心に確認した。
全ソースの網羅監査や描画品質のレビューではない。
P1の配置・保存・Undo基盤を維持し、機能追加や保存形式の変更を伴わない修正に絞った。

## 指摘と対応

| 優先度 | 指摘 | 対応 |
| --- | --- | --- |
| 中 | `ProjectIo.cpp` の一時ファイル保存は、ストリーム破棄時の最終書き込み失敗を確認せず差し替えへ進む。ディスク不足などで既存ファイルを不完全な内容に置き換える可能性がある。 | 明示的にcloseし、成功を確認してからrenameする。プロジェクト・材質保存の共通経路へ適用。 |
| 低 | `UploadRing::Allocate` の `alignedOffset + size` は極端な要求サイズで整数が周回し、容量判定をすり抜ける。通常の呼出値での発生は確認していない。 | オフセットの範囲を先に調べ、残容量との比較に変更。 |
| 低 | プリセット複製と共有形状の材質差し替えに、断面・公開値のID再割当が重複している。複製側だけ `nextId == 0` を拒否せず不正な参照を生成する。通常の読込はこの値を拒否する。 | `CloneSurfacePresetForSpan` に共通化し、必要なIDを事前確認。複製名の変更は呼出側に残す。 |
| 低 | 空の道路帯へ区間を再作成すると、使わない帯と配置のIDも消費する。 | 帯・配置を新規作成するときだけIDを確保。既存のIDと沿道は維持する。 |
| 改善 | Undo／Redoで、直後に捨てる履歴からグラフ・配置・材質を深いコピーしている。 | 履歴からの復元はmoveへ変更。現在の状態を反対側の履歴へ保存するコピーは維持。撤去済みのペイントマスクと固定メモリ量を前提としたコメントも修正。 |

## 検証

- `cmake --preset x64` と `cmake --build --preset x64-debug` が成功。
- `ctest --test-dir build -C Debug --output-on-failure` が成功（1実行ファイル内の全テスト）。
- 追加した回帰テストで公開値のID再割当と始終端値の保持、複製元の保持、不正な次ID・ID不足時の非破壊性、道路帯再利用時の必要ID数を確認。
- 既存テストで共有材質の差し替え、配置の保存往復、Undo／Redoを確認。
- Debugアプリで初期プロジェクトを保存し、再読込して同じファイルへ上書き。保存前後のSHA-256が一致し、両ログに警告・エラーなし。`data/review-cleanup/` に検証資料を保存。3フレーム後の保存は初回描画が約90秒で完了しなかったため検証用プロセスを終了し、`--screenshot-frame 0` で保存経路を確認した。描画性能の原因は未特定。
- ディスク不足・close失敗の注入、GPU転送の極端な要求サイズによる実機試験、Releaseビルド、対話操作と描画の目視確認は未実施。

## 後続の改善候補

`ProjectIo.cpp` はCPUテストターゲットに含まれていない。ファイル書き込みを小さな独立部品へ分離し、最終書き込み失敗時に元ファイルを保持するテストを追加すると、保存の回帰検出を強化できる。
Undoの段数上限は100だが、データ量の上限ではない。大きなグラフと配置でメモリを計測してから、容量による上限や差分履歴の必要性を判断する。
