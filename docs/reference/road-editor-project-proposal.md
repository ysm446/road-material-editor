# 道路・道路付属物エディタ — 派生プロジェクト構想

作成日時: 2026-09-06 10:01
更新日時: 2026-09-06 11:14

## 派生先での採用

本リポジトリでは Road Editor（road-editor）の出発点として採用した。
ハイトマップ中心の仕様を廃止し、実寸3Dパスとメッシュ中心へ移行する。
以下の構想は原案として残し、現在の決定と実装状況は [plan](../plan/plan.md) / [progress](../plan/progress.md) を正とする。

## この文書の位置付け

terrain-graph を土台に、新しいプロジェクトで道路・道路付属物をビジュアライズする
ノードベースのエディタを開発するための構想と初期実装案。
新しいリポジトリへこの文書をコピーして、設計と開発の出発点にする。
terrain-graph 本体の計画を変更するものではない。

ここに記載するノード名・データ型・描画構成は提案であり、実装済みの仕様ではない。
実装開始時に、派生元の最新コードと新プロジェクトの方針に合わせて確定する。

## 目的

パスを引いて道路を作り、道路の端へ路肩、縁石、歩道、側溝、ガードレールなどを
接続していく構造を、ノードグラフで非破壊に編集できるようにする。

道路形状の生成と、白線・汚れ・轍などの表面表現を同じ道路データから生成する。
中心線や道路幅を編集すると、それに依存する付属物と表面表現も追従する。

最初の目的は道路のオーサリングと視覚的な確認とする。
土木設計基準への適合判定、交通シミュレーション、施工用成果物の生成は、
別途要件を定めるまでは対象に含めない。

## 基本方針

- 実際の段差・輪郭・影を必要とする部分はメッシュで作る。
- 白線や汚れのような表面の変化は、PBR マテリアル合成やデカールで表現する。
- 道路ノードはメッシュだけでなく、道路面と左右境界パスを出力する。
- 長さ、幅、高さ、配置間隔は実寸のメートルを基準にする。
- 編集用データを保存し、生成メッシュや描画用データは再生成できるようにする。
- 小さな試作から始め、各段階で起動して編集と描画を確認する。

## 表現手法の使い分け

| 対象 | 基本の表現 | 理由 |
| --- | --- | --- |
| 舗装面 | パスに沿って生成するメッシュ | 高さ、横断勾配、橋などを表現する |
| 路肩・歩道・縁石・側溝 | 道路断面から生成するメッシュ | 段差、輪郭、影が必要 |
| 白線・停止線・矢印 | 路面マテリアルへの合成、またはメッシュデカール | 路面になじむ薄い塗膜として表現する |
| 連続する轍・汚れ・補修跡 | スプラインに沿うデカール | 道路方向に続く模様を編集しやすい |
| 局所的な油染み・泥・ひび | 投影デカール | 位置・角度・大きさを個別に調整できる |
| 深い穴・盛り上がった泥 | メッシュや変位と表面材質 | 表面の材質変更だけでは形状を作れない |
| ガードレール・標識・支柱 | パスに沿うメッシュ生成またはインスタンス配置 | 連続部材と一定間隔の配置を扱う |

### 白線と Depth Bias

路面に薄いポリゴンを重ね、Depth Bias で深度競合によるちらつきを抑える方法は使える。
ただし Depth Bias は深度競合への補助であり、路面形状への追従や下地法線の継承を
自動的に解決するものではない。大きなオフセットは浮きや貫通の原因になる。

最初は道路自身の座標で白線を路面マテリアルに合成する。
この方式では白線のための重複面がなく、深度競合も発生しない。
白線を独立した帯として編集する必要が出たらメッシュデカールを追加する。
近接撮影で塗膜の厚さが必要な場合は、変位や薄い実形状を別途検討する。

## デカールとライティング

デカールは必ずしもライティング後のポストエフェクトではない。
PBR のデカールでは、照明計算へ渡す BaseColor、Roughness、Normal などを変更できる。

```text
路面の BaseColor / Roughness / Normal
                  ↓
         白線・汚れの材質を合成
                  ↓
          直接光・影・IBL を計算
                  ↓
              トーンマップ
```

油染みは色だけでなく粗さも変え、白線は塗料の色と粗さを与える。
下地のアスファルトの凹凸をどの程度残すかも、材質側で制御する。
こうすると白線や汚れも路面と同じ照明・影を受ける。

法線を重ねる場合は、接空間の向きを揃えたうえで RNM を使う。
単純な法線ベクトルの lerp で下地と詳細を合成しない。

法線や視差による凹凸は、実際の輪郭、段差、衝突形状を作らない。
実形状による影が必要な縁石や深い轍にはジオメトリを使う。

### 描画方式の選択肢

| 方式 | 処理する場所 | 用途・注意点 |
| --- | --- | --- |
| マテリアル内の合成 | 路面の照明計算前 | 道路座標を使った白線や連続模様から始めやすい |
| テクスチャへの事前合成 | 編集時などに材質テクスチャを更新 | 描画処理を簡潔にできるが、解像度と更新範囲の管理が必要 |
| GBuffer デカール | 不透明物の材質情報を描いたあと、照明計算前 | ディファード方式の材質バッファを変更する |
| DBuffer デカール | 専用バッファに蓄積し、受け手のマテリアルが参照 | フォワード方式でも採用できるが、深度プリパスや受け手側の対応が必要 |

調査時点の terrain-graph は、メッシュ描画時に直接光と IBL を計算するフォワード方式。
初期実装では既存の PBR 描画を維持し、路面マテリアル内の合成を使う。
任意の物体へ貼れる汎用デカールが必要になった段階で DBuffer を検討する。
デカールのためだけに全面的なディファード化を前提にしない。

## スプラインデカールの仕組み

参考記事の帯状デカールは、記事内では CryEngine の Road オブジェクトと説明されている。
道路だけでなく、畑の畝、轍、水たまりなどにも利用されている。
公式 Road Tool 資料には幅、分割間隔、テクスチャの反復長、描画優先度、
地形を道路へ合わせる機能が記載されている。

以下は同様の機能を自作するための構成案であり、KCD2 内部の描画コードを
確認・再現した仕様ではない。記事の画像だけから、変位やデカールパスの詳細は断定しない。

### 帯状メッシュを使う方式

1. パスを細かい点列にサンプリングする。
   各点で位置、接線方向、幅、始点からの累積距離を求める。
2. 各点の左右へ幅を広げ、隣接する断面を三角形で結んで帯を作る。
   地形用の帯は地形面へ、道路上の帯は生成済みの道路面へ追従させる。
   幅が広い場合や起伏がある場合は横方向にも分割する。
3. 帯へ連続した UV を付ける。
   長手方向は累積距離を反復長で割り、横方向は左端から右端へ割り当てる。
4. 帯の範囲へ材質を合成する。
   テクスチャのマスクで縁をぼかし、色・粗さ・法線などを反映する。
5. 複数の帯は明示的な優先度に従って重ねる。

```text
長手方向 UV = 始点からの道のり / テクスチャの反復長
横方向 UV   = 帯の左端で 0、右端で 1
```

白線の破線や支柱の間隔も、制御点番号や曲線パラメータではなく実距離で管理する。
中心線の距離を共有するか、オフセットした線自身の距離を使うかは用途ごとに定める。
前者は左右の模様の位置を合わせやすく、後者は各線上の実際の間隔を一定にできる。

帯の形状生成と材質合成は独立した機能にする。
同じ帯を、通常の PBR メッシュ、メッシュデカール、テクスチャへのベイク範囲として
利用できる設計にする。

### 深度から投影する方式

パスに沿って厚みを持つ投影領域を作り、画面の深度から復元した表面位置が
その領域内にあるか判定する。領域内の位置から帯の UV を計算し、材質を合成する。

道路以外の車、縁石、橋の下の地面などへ誤って付着しないように、
受け取り対象、投影深度、面の向きなどで適用範囲を制限する。
平面上の距離だけでは、上下に重なる道路を区別できない。

### 主な実装課題

- 急カーブで帯の内側が重なる、または外側が伸びる問題。
- 区間の継ぎ目で UV、法線、透明度が不連続になる問題。
- 重複した区間を二重合成して濃くなる問題。
- 下地の LOD や変位が変わったときの貫通・浮き。
- 細い白線や破線の遠景でのちらつき。適切なフィルタリングが必要。
- 長い道路全体の再生成コスト。区間単位のキャッシュと更新範囲を検討する。
- 交差点、合流、分岐での形状と模様の接続。専用の処理として扱う。

## ノードグラフの構成

道路ノードから道路面と左右境界を出し、それを次の部品の入力にする。
幅を複数ノードへ手入力して位置を合わせる構成を避け、接続関係から導出する。

```text
中心パス + 幅・縦断高さ・横断勾配
                  ↓
               道路生成
                  ├─ 道路面 → 白線
                  ├─ 道路面 → 汚れ・轍
                  ├─ 左境界 → 路肩 → 外側境界 → 縁石・歩道
                  └─ 右境界 → 路肩 → 外側境界 → ガードレール配置
```

道路幅を変えると路肩が追従し、路肩幅を変えると縁石やガードレールも移動する。
白線は道路面上の横距離で位置を指定する。

道路網の接続関係と、生成処理の依存グラフは区別する。
道路網には環状道路などのループを許せるが、ノード評価の依存関係は DAG とする。

### データ型の候補

| 型 | 役割 |
| --- | --- |
| Path | 中心線や境界線。位置、方向、距離に沿う属性を参照できる |
| RoadSurface | 道のりと横距離から、位置・法線・接線などを取得する道路面 |
| CrossSection | 車道・路肩・縁石などの幅、高さ、勾配を定める断面 |
| Mesh | 描画・書き出し用の生成形状 |
| Material | PBR 材質とテクスチャ |
| DecalSet | 材質、適用範囲、優先度、受け取り対象など |
| InstanceSet | 標識、支柱などの配置位置・姿勢とアセット参照 |

ノードはデータを出力し、描画側がそれをシーンとして表示する。
ノード評価中に描画や共有シーンの変更を直接実行する構成は避ける。

## 道路と地形の関係

既存 Path は地形の正規化 UV を基本とし、高さのずれを点ごとに持つ。
道路専用版では、実寸の道のり、縦断高さ、横断勾配、左右境界を持つ道路データを追加する。

地形に沿う小道と、縦断を設計する舗装道路を扱い分ける。
舗装道路は地形の細かな凹凸へそのまま追従させず、道路面を先に定義し、
周囲の地形を切り土・盛り土で合わせることができるようにする。

橋や高架を扱うには、同じ水平位置に複数の高さの面が存在できなければならない。
ハイトマップだけで道路本体を表現せず、道路メッシュを独立した形状として保持する。

地形の加工と道路生成が相互参照して循環しないよう、入力地形から道路を設計し、
確定した道路面を使って加工後の地形を生成する、といった一方向の評価にする。

## 派生元から活用するもの

調査時点の terrain-graph には次の土台がある。

- C++20 / CMake / vcpkg / Windows / DirectX 12 / HLSL SM 6.6。
- Dear ImGui とノードエディタ、グラフ保存、編集履歴。
- Path の点・エッジ、曲線サンプリング、地形上の編集、パスマスク。
- PBR 合成、直接光と IBL、露出、トーンマップ。
- GPU リソース管理、シェーダコンパイル、非同期の合成評価。

確認する主なファイルは以下。パスは派生元リポジトリからの相対パス。

- `docs/plan/goals.md`、`docs/plan/plan.md`、`docs/plan/progress.md`

調査時点ではマスクに DAG とキャッシュがあり、材質合成は線形の部分が残っている。
メッシュや道路面を流せる汎用の幾何評価器が既にある前提では進めない。
また、プレビューは地形用の平面を中心とするため、複数メッシュとインスタンスを
表示するシーン構成を追加する必要がある。

## 初期実装の順序

### 第 1 段階 — 派生プロジェクトの起動

- プロジェクト名、実行ファイル名、保存形式の扱いを決める。
- 既存のノード編集と PBR プレビューがビルド・起動できる状態を作る。
- 地形とは別のメッシュを表示できる最小限のシーン構成を用意する。

確認: 新プロジェクトとして起動し、保存・再読込と PBR 表示ができる。

### 第 2 段階 — 中心パスから道路を生成

- 分岐のない中心パスから、一定幅の道路メッシュを生成する。
- 実距離に基づく UV と道路面・左右境界の出力を作る。
- 平面だけでなく、曲線と緩やかな縦断変化を確認する。

確認: パスと道路幅を変更すると、メッシュと境界が更新される。
テクスチャの反復長が制御点の配置に依存しない。

### 第 3 段階 — 路肩と白線

- 左右境界へ路肩を接続する。
- 道路座標を使い、実線・破線を路面マテリアルに合成する。
- 白線の色・粗さと下地の細部を制御する。

確認: 道路幅を変更すると路肩と白線が追従する。
光の方向と粗さを変え、白線が路面と一緒に照明・影を受けることを確認する。

### 第 4 段階 — スプラインデカール

- 任意幅・反復長・横オフセットを持つ帯を生成する。
- 汚れ、轍、補修跡を道路面に沿って配置する。
- 合成優先度と端のフェザーを実装する。

確認: 急カーブ、区間の継ぎ目、重なり、遠景での表示を確認する。

### 第 5 段階 — 付属物と汎用デカール

- 縁石・側溝の断面生成、支柱・標識などのインスタンス配置を追加する。
- 道路以外にも貼る要求に合わせて DBuffer などの汎用投影デカールを検討する。
- 対象の制限、投影範囲、法線合成、深度プリパスを設計する。

その後に交差点、合流、幅の変化、切り土・盛り土、橋、LOD、書き出しを段階的に追加する。
交差点は帯を重ねるだけで完了とせず、形状の接合と車線表示を別途設計する。

## 初期段階で決めること

- 対象とする道路規模と必要な近接表示の精度。
- 道路の高さを地形から導く場合と、縦断として指定する場合の操作。
- 複数メッシュを扱うシーンと、ノード出力の関係。
- 新プロジェクトの保存形式と、terrain-graph の素材・地形を取り込む方法。
- 最初の書き出し対象をメッシュと PBR テクスチャのどこまでにするか。
